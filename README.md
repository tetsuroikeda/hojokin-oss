# hojokin

補助金の申請を、社長と担当者が自社で進めるための Claude Code のプラグインです。
専門家に頼めない中小企業でも、補助金を探すところから、申請書を書き、電子申請の画面に入れ（一時保存まで）、採択後の報告までを、Claude と話しながら進められます。

**デモ動画**：準備中（提出のときにここへリンクを入れます）。

- 要件の正本は [SPEC.md](SPEC.md)、作り方の正本は [docs/DESIGN.md](docs/DESIGN.md)、作るときのタスクは [docs/TASKS.md](docs/TASKS.md) です。
- この README は、ハッカソンの期間（2026年11月3日〜8日）の終わりの形を書いています。

## 3分で分かる要約

- **何を作ったか**：補助金を探す → 公募要領を読む → 書類を整理する → 申請書を書き、別の目（審査役）が確かめる → 電子申請の画面に入れる → 採択後の報告、までを手伝う Claude Code のプラグインです。skill・subagent・hooks と、道具のコードで組んでいます。
- **誰のためか**：専門家に頼めない中小企業の社長と担当者です。
- **どう動かすか**：会社ごとに空のフォルダを作って Claude で開き、「うちで使える補助金ってある？」のように話しかけます。提出のボタン、パスワード、確認・誓約・同意のチェック欄は、hooks とコードで止め、人が行います（下の「必ず守っていること」）。
- **どう確かめたか**：自動のテスト（pytest）は 2357件が通りました（11月7日の版）。振る舞いのテスト（`claude plugin eval`）は77のケースを1回ずつ流しました。そのうち9つのケースを、プラグインあり・なしで3回ずつ流すと、合格率は、あり 23/26（88%）、なし 6/26（23%）で、差は 65 ポイントでした（下の「確かめたこと」）。
- **どの制度で確かめたか**：「省力化投資補助金（一般型）」と「小規模事業者持続化補助金（一般型・通常枠）」の2つです。ほかの制度は、これから確かめます。まだ合格していないテストと、確かめていないことも、下に書いています。

## 何をするプラグインか

- **探す・決める**：会社のことを聞き取り、使えそうな補助金・助成金を「公募中」「公募予定」「例年公募がある」に分けて示します。要件、義務、返還の条件、自己負担、二重受給を、出典のページを付けて説明します。結果は「補助金の候補.docx」にまとめます。
- **準備**：公募要領を取り込み、出典のページ付きの「制度データ」を作ります。制度の概要と流れ（概要と流れ.docx）、必要な書類の一覧、締切と日程を作り、制度の質問に、資料の文とページを付けて答えます。資料になければ推測せず、事務局への問い合わせ文の案を作ります。
- **書類**：社長がフォルダに入れた決算書や見積書を、原本の置き場へ移して名前を付け直し、提出に合わせた写しを作ります。不備（期限切れ、名義の違い、交付決定の前の発注など）を、重さを付けて示します。
- **書く・確かめる**：社長の少ない言葉から、構想役が投資の効果の筋書きを3つ（堅実・標準・積極）示し、社長が選びます。前提と根拠のある財務モデルを作り、そこから数字を取って、Word・Excel の様式に、書式を崩さずに書き込みます。前後の比較・数値計画・工程表の図と、会社のフォルダの写真も入れます。書いたときとは別の目（審査役）が確かめ、直してから完成にします。審査の受け答えの練習もできます。
- **記録**：会社について覚えたこと（事実、社長が直した言い回し、指摘）を会社のフォルダに残し、2件目からは聞き直しを減らします。書類の前の版を見る・戻すこともできます。
- **電子申請の入力**：担当者が `/hojokin:nyuryoku` を呼んだときだけ、Claude のブラウザで申請画面に入力し、一時保存まで進めます。ログイン、確認・誓約・同意のチェック欄、最後の「提出」は、担当者が行います。
- **今の状態**：締切、書類の揃い具合、不備、申請書の進み具合、採択後の5年先までの報告の期限を、「今の状態.html」と「今の状態.xlsx」でいつも見られるようにします。

品質を確かめた制度は、「省力化投資補助金（一般型）」と「小規模事業者持続化補助金（一般型・通常枠）」の2つです。ほかの制度でも、公募要領から制度データを作れば、プログラムを変えずに動く作りにしています（品質は確かめていません）。

## 入れ方と使い方

### 入れ方（Claude のデスクトップアプリ）

1. デスクトップアプリの「設定」→「プラグイン」→「＋ 追加」→「リポジトリから追加」を選びます。
2. このリポジトリ（GitHub の公開のリポジトリ）の場所を入れて、hojokin を足します。リポジトリの根の `.claude-plugin/marketplace.json` が、根にあるプラグインを指しています。
   - 画面からは、手元のフォルダを足せません（実験 E4）。

ターミナルでは、次のコマンドで入ります（Claude Code 2.1.317 の `claude plugin install --help` に `--marketplace` があることは確かめました。このコマンドで実際に入れることは、期間中は確かめていません）。

```sh
claude plugin install hojokin --marketplace tetsuroikeda/hojokin-oss
```

### 使い方

1. 会社のフォルダにする、新しい空のフォルダを作ります（下の「初回の準備」と「使うときの注意」を先に読んでください）。
2. デスクトップアプリで、そのフォルダを開きます。モードは auto を選ぶよう勧めます（会社のフォルダの中の読み取りと編集が、確認なしになります）。
3. 「うちで使える補助金ってある？」のように、ふだんの言葉で話しかけます。どの段階の skill を使うかは、Claude が選びます（下の「段階と skill の一覧」）。
4. 申請画面への入力だけは、担当者が `/hojokin:nyuryoku` を呼びます。「申請画面に入れて」と頼んでも、Claude は自分では始めず、このコマンドを案内します。

## 初回の準備

- **Mac の開発ツール**：補助プログラムは、Mac に入っている `/usr/bin/python3` で動きます。開発ツールが入っていない Mac では、「ターミナル」で `xcode-select --install` を実行し、出てきた画面に従って入れてから、Claude を開き直してください。補助プログラムが動かないときは、プラグインが書き込み・Bash・ブラウザの道具を止め、同じ案内を Claude に渡します。
- **ライブラリの準備は要りません**：使うライブラリ（版の履歴の dulwich、PDF を読む pypdf、Excel を作る openpyxl など）は、Python だけで書かれたものをプラグインに同梱しています（`lib/vendor/`）。初回の通信や pip の準備はありません。
- **LibreOffice（あれば）**：申請書の PDF の写しを作るときと、Excel の数式を計算し直すときに使います。入っていないときは、その操作を案内します。
- **Claude in Chrome（画面入力に勧めます）**：書類の添付までツールが行えます。デスクトップアプリの内蔵ブラウザでは添付ができないので、添付は担当者が行います。ターミナルでは `/chrome` で有効にします。
- **会社のフォルダを作る**：どの skill も最初に、今のフォルダが会社のフォルダか（目印の `.hojokin/` があるか）を確かめ、なければ「このフォルダを〇〇社の会社のフォルダにしますか」と聞きます。了承すると、道具が、目印、フォルダの形、版の履歴、`.claude/settings.json`（外を読み書きさせない設定と、書き換えを止める規則）を一度に用意します。
  - 次のフォルダは、会社のフォルダにしません：ホームのフォルダとそれを含むフォルダ、ディスクの根、前から `.git`・`.gitignore`・`.claude/settings.json` があるフォルダ。そのときは、新しいフォルダを作って始め、元の書類は場所を伝えて取り込むよう案内します。

## 会社のフォルダの形

```
<会社のフォルダ>/
├─ 今の状態.html          まずこれを開く。進み具合の画面（見るだけ。開くたびに作り直す）

├─ 補助金の候補.docx       探した結果
├─ 財務モデル.xlsx         会社の数字の土台（前提と根拠、既存事業・新事業・合算）
├─ 入れ口/                書類をとりあえず入れるフォルダ（ほかの場所に入れてもよい）
├─ 原本/                  受け取った書類。読み取り専用。名前は「<日付>_<種類>_<相手先>.pdf」の形
├─ 案件/
│   └─ <年>_<制度>_<回>/
│       ├─ 概要と流れ.docx     制度の概要、要件と義務、手続きの流れと期限、必要書類

│       ├─ 1_申請/
│       │   ├─ 申請書/         計画書、入力シート、根拠対照表
│       │   └─ 添付する書類/   原本から作った写し
│       └─ 2_交付申請/ … 4_効果報告/1年目/ …（制度データの手続きの段階から作る）
├─ 見るだけ/              前の版や提出版を見たいときだけ出す（開くたびに片付ける）
```

## 段階と skill の一覧

skill の名前には、プラグインの名前が前に付きます（例：`/hojokin:sagasu`）。ふだんは名前を呼ばずに話しかければ、Claude が選びます。

| 段階 | skill | すること | 社長の言い方の例 |
|---|---|---|---|
| 探す・決める | `sagasu` | 使える補助金・助成金を探し、どれに申請するかを決める | 「機械を入れたいけど、何かお金が出ない？」 |
| 準備 | `junbi` | 制度データ・概要と流れ・書類の一覧・日程を作る。制度の質問、締切、外への依頼と待ち、改訂、採択後の手続きへの切り替え | 「いつまでに出せばいい？」「受かったって連絡が来た」 |
| 書類 | `shorui` | 原本の整理、名前の付け直し、写しの作成、不備のチェック、見積書の金額の照合 | 「決算書を入れておいたから見ておいて」 |
| 書く・確かめる | `kaku` | 財務モデル・計画書・入力シート・採択後の報告書を作り、審査役が確かめて直す。差し戻しへの対応、説明の練習 | 「申請書を書き始めて」「本番みたいに相手して」 |
| 記録 | `kiroku` | 会社について覚えていることを見る・直す。書類の前の版を見る・戻す。提出版を残す | 「何を知ってるか見せて」「前の書き方に戻して」「出し終わった」 |
| 電子申請の入力 | `nyuryoku` | 申請画面に入力し、一時保存まで進める | 担当者が `/hojokin:nyuryoku` を呼んだときだけ動く |

- subagent は3つです。`shinsa`（審査役。書いたときとは別の文脈で申請書を確かめる）、`yomitori`（読み取り役。公募要領や書類を読み取る）、`kousou`（構想役。投資の効果の筋書きと財務モデルの式の案を出す）。
- hooks は、開いたとき・社長が送ったとき・道具を使う前と後・応答を終えたとき・審査役が終わったときに動き、下の決まりを守ります。

## 必ず守っていること

Claude の判断に任せられない決まりだけを、道具の中のコード、hooks、公式の設定で止めています。すり抜けたものは、結果の確かめ（ハッシュや書式の比較）で見つけて戻します（DESIGN 5章）。

- **提出ボタンを押さない**：「提出」「送信」「申請する」「確定」「完了」などを含むボタンは押させません。押してよいボタン（次へ・一時保存・戻るなど）だけを通します。
- **確認・誓約・同意のチェック欄に入れない**：これらの欄は担当者が入れます。ツールが入れる欄（加点の選択など）でも、名前が読み取れない欄には入れません。
- **パスワードを扱わない**：ログインは担当者がブラウザで行います。
- **添付するのは、決まった写しだけ**：申請書類のフォルダの「添付する書類」にある写しのうち、入力シートの添付する書類に当たるものだけです。
- **画面入力は、担当者が呼んだときだけ**：`/hojokin:nyuryoku` を呼んだ記録がないと、ブラウザの道具のクリック・入力・添付を止めます。
- **Word・Excel の様式と書式を壊さない**：書いてよい範囲だけに書き、範囲の外が1か所でも変わっていたら保存しません。その場のコードで書き換えた場合も、応答の終わりに比べて戻します。
- **原本と公式資料を1バイトも変えない**：読み取り専用にし、開いたときと応答の終わりに、置いたときのハッシュと照らします。変わっていたら版の履歴から戻し、社長に知らせます。
- **版のファイルを増やさない**：「_v2」「最終」「修正版」「コピー」などの名前のファイルを作らせません。
- **会社のフォルダの外を読まない・書かない**：ファイルの道具は、会社のフォルダの外（別の会社のフォルダや認証情報など）を読み書きしません。外の書類は、社長が場所を伝えたものだけを写して取り込みます。
- **書類と履歴を外に送らない**：会社のフォルダの版の履歴は、送り先を持ちません。
- **補助プログラムが動かないときは止める**：Python が動かない・時間内に終わらないときは、書き込み・Bash・ブラウザの道具を止めます（守りが気づかないうちに外れないように）。
- **会社のフォルダでないフォルダでは何もしない**：hooks は何も止めず何も書かず、道具も、補助金を探すことと会社のフォルダを作ること以外は動きません。

### 守りが掛かる範囲

- hooks が使う前に見る道具は、書き込みの道具（Write・Edit・NotebookEdit）、Bash、ブラウザの道具（Claude のブラウザ〈内蔵ブラウザ〉・Claude in Chrome・computer-use）、読む道具（Read・Grep・Glob など）です（`hooks/hooks.json`）。道具は、名前に `Claude_Browser`・`claude-in-chrome`・`computer-use` の文字が入るかで見分けます。名前に `computer-use` を含む画面操作の道具は、会社のフォルダではすべて止めます。
- Bash は、コマンドの中身を見ていません。止めるのは、補助プログラム（Python）が動かないときだけです（`hooks/pre_tool_use.py`・`hooks/run.sh`）。会社のフォルダの中で Bash が変えたものは、応答の終わりの確かめ（原本と公式資料のハッシュ、様式の書式の比べ、版の名前のファイル）で見つけます。Bash で会社のフォルダの外を読み書きすることや、外へ送ること（curl など）は、hooks では見ていません。Claude Code の許可の確認に任せます。
- 名前に上の文字を含まない道具（たとえば、別の JavaScript を動かす道具や、ターミナルに打ち込む道具）でブラウザを操作したときは、この守りは掛かりません。Claude Code の許可の確認に任せます。Claude のブラウザと Claude in Chrome の中での JavaScript の実行は止めています。
- 「書類と履歴を外に送らない」は、版の履歴（Git）に送り先を持たせないことです。ブラウザでどのページに移るか（http・https のページへの移動は、どこでも通します）と、Web から取るときの行き先、Bash で送る先は、hooks では絞っていません。Claude Code と、ブラウザ側のサイトの許可に任せています（`lib/browser_guard.py`）。
- 「パスワードを扱わない」は、画面の欄の種類が password の欄と、名前に「パスワード」を含む欄に入れないことです。ほかの名前の欄（認証コード・暗証番号など）は見分けていないので、担当者が入れてください（`lib/browser_guard.py`）。
- 守りが相手にしているのは、協力的な Claude と、Git を知らない社長のうっかりです（DESIGN 5章）。書類や画面に書かれた文に Claude が乗せられる場合までは、止めきれません。

## Claude に任せていること

上の決まりのほかは、できるだけ Claude の判断に任せています。モデルが進むほど、細かい指定は、かえって書く力を縛るためです。

2026年11月7日に、計画書の書き手と審査役に渡していた決まりを洗い出し、「守るもの」と「書き方を縛っているだけのもの」に分けました。

- **守るもの**：事実を作らない、本文の数字に出典を付けて財務モデルと合わせる、様式の項目と欄を書く、上限を超えない。これらは、コードの確かめと審査役で守り続けます。
- **任せたもの**：段ごとに入れる事実の並べ方、書き出しや文の長さの指定、図を置く目安、文体の観点を書き方の型として当てること。これらは「目的と観点」に替え、書き方は Claude に任せました。
- **分量**：公募要領に上限や目安がある所はそれを守ります。ない所は字数を決めず、審査役が読んで「足りない」「長すぎる」を判断します。
- **制度ごとの知見**：その制度で書くときだけ渡し、ほかの制度の計画書に混ぜません。

直す前のデモの会社では、数値計画を書けずに【空欄】9か所で止まり、審査役まで進めませんでした。直した後は【空欄】0か所で書き切りました。審査役の要修正11件は、すべて中身についての指摘で、書き方の好みによる要修正は0件でした。そこから要修正0件まで直しています。なお、同じときに社長役の答えも足したので、この差は書き方の直しだけによるものではありません。

## 使うときの注意

- **会社のフォルダは、同期されないフォルダに作ってください。** iCloud Drive・Google ドライブ・OneDrive・Dropbox などで同期されるフォルダに置く形（版をファイルで残す形）は、期間中は選べません。
- **デスクトップアプリでは、会社のフォルダそのものを開いてください。** 目印（`.hojokin/`）は開いたフォルダだけで確かめ、親のフォルダはさかのぼりません。会社のフォルダを含む親のフォルダで開くと、会社のフォルダと見なされず、守りの hook も働きません（11月6日のリハーサルで分かりました）。
- **同じ会社のフォルダを、2つの Claude で同時に開かないでください。** 版の履歴や台帳への書き込みが、ぶつかることがあります。
- **本物の申請画面に入れる前に、制度ごとの規約と遵守事項を、担当者が確かめてください。** 持続化補助金の申請システムの操作手引きには、BOT などによる操作を禁じる定めがあります。本物の画面では、ツールが作った入力シートを見ながら、担当者が自分で入れることを勧めます。
- 書類の作成者と申請者は、事業者自身です。このツールは、事業者が自分で進めるための道具です。申請画面の支援者の欄には、「このツールは支援者には当たりません。人の支援者がいる場合は正直に書いてください」と案内します。

## 持続化に対応したときに先に入れた直し

1件目の省力化で作ったプログラムに、2件目の持続化の制度データを足すだけで、段階ごとの道具が動くかを確かめました（B1a・B1b。T0-1）。持続化の制度データを足したコミット（件名が「B1a 持続化：」「B1b 持続化：」のもの）には、プログラムの変更がありません（`tests/test_T0_1.py` がこの件名でコミットを探して確かめるので、これらのコミットはまとめたり件名を変えたりしません）。

その前に、別のコミットで、次の直しを1つだけ入れました。

| コミット | 直したこと | 理由 |
|---|---|---|
| b6cae95 | 入力先が申請画面の様式を、確かめの注意の「書き込む位置をまだ対応づけていない」に挙げない（lib/kakunin.py） | 持続化の様式は画面に入力し、入力シートの欄で書くので、書き込む位置を持たない。注意に挙がると、Claude が様式の対応づけをしようとして止まるおそれがある。制度の名前ではなく、制度データの様式の「入力先」（画面かファイルか）で分ける一般化で、省力化の動きは変わらない |
