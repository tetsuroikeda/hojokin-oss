# hojokin

hojokin（日本語で「補助金」）は、日本の中小企業が補助金を申請し、受け取った後の報告まで進めるのを手伝う、Claude Code のプラグインです。申請を支援する専門家に頼めない会社でも、社長と担当者が Claude と話しながら、自社で進められます。手続きの手間を減らし、本業に力を注げるようにします。

**デモ動画**：準備中（提出のときにここへリンクを入れます）。架空の町工場で、補助金を探すところから採択後の手続きまで、実際にプラグインを動かした画面で見せます。

この README は、ハッカソン「Built with Claude: Japan 2026」の期間（2026年11月2日〜8日）の終わりの形を書いています。

## 日本の補助金の流れ（先に読む方へ）

補助金は、国や自治体が、中小企業の設備投資や販路開拓などの費用の一部を出す制度です。原則として返す必要はありませんが、審査があり、条件を守らないと返還を求められることがあります。細かい流れは制度ごとに違いますが、おおむね次のとおりです。

1. **公募**：制度ごとに「公募要領」が出ます。要件、補助の対象になる経費、締切、義務を定めた、数十ページの募集の案内です。
2. **申請**：会社が、事業の計画書と、制度が決めた書式（「様式」。Word・Excel のファイルや、申請画面の欄）を、多くは電子申請で出します。
3. **採択**：審査で、補助する会社に選ばれます。
4. **交付決定**：補助する経費と金額が、正式に決まります。原則として、これより前に発注・契約した経費は補助されません。
5. **実績報告**：設備を入れるなどの事業を行い、使った経費を報告します。補助金は、その確かめの後に支払われます（後払い）。
6. **効果報告**：その後も、生産性や賃金などの成果を報告します（省力化投資補助金では5年先まで）。

## 3分で分かる要約

- **誰の、どんな課題か**：補助金は、効率化・新しい事業・販路開拓の力になります。それでも、専門家に頼めない会社は、「どれが使えるか分からない」から「採択の後も大変」まで、5つの壁にぶつかり、手続きを本業の合間に手探りで進めています。作者は、こうした経営者の相談を100件以上受けてきました。ハッカソンのテーマ「本来、誰にでも届くべきものを。」に沿い、専門家に頼める会社でなくても、補助金を使えるようにします。
- **何を作ったか**：補助金の手続きを、最初から最後まで手伝う Claude Code のプラグインです。
  - 探す → 公募要領を読む → 書類を整える → 申請書を書く → 審査役（審査員の目で読み直す subagent）が確かめる → 電子申請の画面に入れる → 採択後の報告
  - 提出ボタンを押す、パスワードを入れる、確認・誓約・同意の欄にチェックする。この3つは、Claude にさせず、人が行います。
- **どう使うか**：1社に1つ「会社のフォルダ」を作り、Claude のデスクトップアプリで開いて話しかけます（初めの準備は8章）。たとえば「機械を入れたいけど、使える補助金はある？」と聞くと、候補の一覧（Word）ができます。申請の段階では、公式の Word・Excel の様式に書き込んだ申請書ができます。締切と次の作業は「今の状態.html」で、いつでも見られます。
- **Claude Code をどう活かしたか**：手続きの段階ごとの skill（6つ）、役目の違う3つの subagent、守りと知らせの hooks、ブラウザの MCP のツール、計算と書き込みをする Python のスクリプトを使い分けています。守るべき所はコードと hooks で固め、書き方は Claude に任せる、という線を引きました。作るときも、仕様と2種類のテストを基準にして、Claude Code で作りました。
- **どの補助金で確かめたか**：国の2つの補助金です。「省力化投資補助金（一般型）」（人手を減らす設備やシステムへの投資が対象。以下、省力化）と、「小規模事業者持続化補助金（一般型・通常枠）」（小さな会社の販路開拓などが対象。以下、持続化）です。ほかの補助金の申請書には、まだ使っていません。
- **どう確かめたか**：
  - 自動のテスト（pytest）：11月8日の版で全部を流し、2369件が通りました（落ちたものは0件）。
  - 振る舞いのテスト（`claude plugin eval`。Claude に実際に頼み、結果を採点する）：77のケースを1回ずつ流し、74が合格しました。最初の合格は66で、結果のばらつき（同じケースでも、回によって合否が変わること）で落ちたものの流し直しと、採点・手順の直しをした後の数です。3回ずつ流せた26のケースでは、3回とも合格したのは15で、ばらつきが残っています。落ちたケースと理由は9章にあります。
  - プラグインあり・なしの比較：9つのケースを3回ずつ流し、合格率は、あり 23/26（88%）、なし 6/26（23%）で、差は65ポイントでした（流れなかった1回を除いています）。
  - 架空の町工場で、省力化の申請書を、審査役の「要修正」（直す必要があるとした指摘）が0件になるまで書き上げました。

## 1. 解決する課題

### 社長と担当者がぶつかる5つの壁

中小企業がやりたいことはさまざまで、補助金はその後押しになります。けれども、専門家に頼めない会社では、社長や担当者が本業の合間に、手探りで進めています。そこには、次の5つの壁があります。

| 壁 | 中身 |
|---|---|
| どれが使えるか分からない | 国・都道府県・市区町村の制度があり、今の公募と、例年の公募の見込みを調べる手間がかかる |
| ルールが多すぎて分からない | 公募要領は数十ページあり、要件・義務・返還の条件・締切が散らばっている |
| 書類が膨大 | 決算書・見積書・様式などを集め、期限切れ・名義の違い・交付決定の前の発注のような不備を見つける必要がある |
| 採択される計画書が書けない | 審査の観点に沿い、数字の根拠と財務の計画をそろえた計画書は、慣れないと書けない |
| 採択の後も大変 | 交付申請・実績報告・効果報告と、手続きが続く（制度によっては5年先まで） |

hojokin は、この5つの壁に1つずつ応えます（2章）。作者が実務で見てきた不備の型・審査の観点・計画書の構成の型は、同梱の知見（`knowledge/`）として組み込んでいます。

### ハッカソンの後も、誰がどんな場面で使うか

- **申請のたびに**：社長と担当者が、補助金を探すところから、申請、採択後の報告まで、同じ会社のフォルダで続けます。会社のフォルダは、書類・申請書・会社の記録を入れ、版の履歴を残すフォルダです（形は8章）。
- **採択の後の数年間**：会社のフォルダを開くたびに、hooks が締切と次の作業を示します。採択後の報告の期限（省力化の効果報告は5年先まで）も、同じ画面に並びます。
- **2件目の申請**：1件目で覚えた会社の事実を使い、聞き直しを減らします。
- **新しい制度**：公募要領から制度データ（下の2章）を作れば、プログラムを変えずに動く作りです。制度ごとに品質を確かめて広げます（6章）。

## 2. できること

### 5つの壁と、hojokin の段階

| 壁 | 段階（skill） | hojokin がすること |
|---|---|---|
| どれが使えるか分からない | 探す・決める（`sagasu`） | 選択肢の画面で会社のことを聞き、国と都道府県・市区町村の補助金・助成金を「公募中」「公募予定」「例年公募がある」に分けて、出典つきで示す。結果は「補助金の候補.docx」にまとめる |
| ルールが多すぎて分からない | 準備（`junbi`） | 公募要領から、要件・対象の経費・期限・様式を出典のページ付きでまとめた「制度データ」を作る（ほかの段階は、これを見て動く）。これを元に、概要と流れ（Word）・書類の一覧・日程を作る。制度の質問には資料のページを示して答え、書かれていなければ推測せず、問い合わせ文の案を作る |
| 書類が膨大 | 書類（`shorui`） | 社長がフォルダに入れた決算書や見積書を原本の置き場へ移し、名前を付け直し、提出に合わせた写しを作る。不備（期限切れ、名義や金額の違い、交付決定の前の発注など）を、重さを付けて示す |
| 採択される計画書が書けない | 書く・確かめる（`kaku`） | 構想役（投資の効果の筋書きを考える subagent）が筋書きを3つ示し、社長が選ぶ。財務モデル（Excel）から数字を取り、公式の Word・Excel の様式に、書式を崩さず書き込む。審査役が別の文脈で確かめ、直してから完成にする |
| 採択の後も大変 | 準備・書く（`junbi`・`kaku`） | 採択の通知から交付申請の期限を出し、採択後の段階へ切り替える。差し戻しには、指摘と提出版を照らして直す。実績報告・効果報告の書類も作る |

表のほかに、次のこともします。

- **探す・決める**（`sagasu`）：要件・義務・返還の条件・自己負担・二重受給（同じ経費で、複数の補助金を受けること）を、出典のページを付けて説明します。
- **準備**（`junbi`）：外の機関に頼む書類の依頼と待ち、公募要領の改訂も追います。Claude が作った制度データは、出典のページで確かめてから使ってください（読み取りの精度は9章）。
- **書類**（`shorui`）：見積書・請求書・納品書の金額も照らし合わせます。
- **書く・確かめる**（`kaku`）：前後の比較・数値計画・工程表の図と、会社のフォルダの写真を、計画書に入れます。数字と出典の対応表（根拠対照表）も作ります。審査の受け答えの練習もできます。
- **電子申請の入力**（`nyuryoku`）：担当者が `/hojokin:nyuryoku` を呼んだときだけ、Claude のブラウザで申請画面に入力し、一時保存まで進めます。入力する値は、申請画面と同じ項目・順番で値をまとめた「入力シート」から取ります。ログイン、確認・誓約・同意のチェック欄、最後の「提出」は、担当者が行います。本物の申請画面で使う前に、8章の注意を読んでください。
- **記録**（`kiroku`）：会社について覚えたこと（事実、社長が直した言い回し、指摘）を会社のフォルダに残します。書類の前の版を見る・戻すこと、提出版を残すこともできます。
- **今の状態**：締切、書類の揃い具合、不備、申請書の進み具合、採択後の報告の期限を、「今の状態.html」と「今の状態.xlsx」でいつも見られるようにします。

skill の名前には、プラグインの名前が前に付きます（例：`/hojokin:sagasu`）。ふだんは名前を呼ばずに、「機械を入れたいけど、何かお金が出ない？」「いつまでに出せばいい？」「申請書を書き始めて」のように話しかければ、Claude が選びます。

## 3. デモ

**デモ動画**：冒頭のリンクです（準備中）。場面と作り方は [docs/video/README.md](docs/video/README.md) にあります。

動画は、5つの壁と作者の実務（相談100件以上）から始まり、壁に1つずつ対応する STEP 1〜5（探す・調べる・書類・書く・採択後）を見せます。STEP 4 では、書いた後に審査役が確かめ、申請の画面に入れます。続けて、開いたときに Claude が次の作業を示す場面、2件目（持続化）で1件目の事実を使い回す場面、始め方、作り方を見せます。

## 4. Claude Code の活かし方

### 製品の中で：機能を目的で使い分ける

| 機能 | 何に使うか | なぜその機能か |
|---|---|---|
| skill（6つ） | 探す・準備・書類・書く・記録・入力の段階ごとの手順とスクリプト | 社長の言葉から、Claude が段階を選べるように。申請画面への入力の skill だけは、Claude が自分では呼べない設定にし、担当者が呼ぶ |
| subagent：審査役（`shinsa`） | 書き終えた申請書を、書いたのとは別の文脈で確かめる。opus を、深く考える設定で使う | 書いた本人の文脈では、自分の思い込みに気づきにくいため |
| subagent：読み取り役（`yomitori`） | 公募要領・様式・書類を読み取る。量と難しさで haiku・sonnet・opus を使い分ける | 量の多い読み取りで、本体の文脈を守るため |
| subagent：構想役（`kousou`） | 少ない情報から、投資の効果の筋書きと財務モデルの式の案を出す。opus を、深く考える設定で使う | 筋書きを考える所だけを、別に考えさせるため |
| hooks（守り） | Claude Code のツールを使う前と後、応答の終わりに動く。原本と公式資料を守り、提出ボタンを押させず、会社のフォルダの外を読ませない | Claude の判断に任せられない決まりを、確実に止めるため |
| hooks（知らせと記録） | 開いたとき・社長が送ったとき・審査役が終わったときに動く。開いたときに締切と次の作業を示す。社長の手直しと、審査役の結果を記録する | 社長が聞かなくても次の作業が分かり、記録が抜けないように |
| 選択肢の画面（AskUserQuestion） | 社長に1問ずつ、勧める案と聞く理由を添えて聞く | 社長が迷わず答えられるように |
| ブラウザの MCP のツール（Claude in Chrome・Claude のブラウザ） | 電子申請の画面に入力し、一時保存まで進める。hooks は、このツールの名前で守りを掛ける | 入力の手間を減らし、提出は人が押す形にするため |
| Python のスクリプト | 財務モデルの計算、Word・Excel への書き込み、書類と数字の照合 | 数字を作らず、様式の書式を壊さないため |

### ほかではあまり見ない使い方

- **引用を本文と照らす hook**：応答を終えるとき、Stop の hook が、答えの中の公募要領の引用（「」と資料名・ページ）を、そのページの本文と照らします。本文にない引用があれば、応答を終わらせずに Claude に答え直させます（`hooks/inyou_hooks.py`）。
- **審査役の結果を、書き手に通さない**：審査役が終わると、hook が報告を本体（書き手の Claude）を通さずに保存します。完成かどうかは、保存した結果で判定します（`hooks/shinsa_hooks.py`・`lib/shinsa_result.py`）。
- **守る所はコードで固く、書き方は Claude に任せる**：下の節のとおりです。

### 守る所はコードで固く、書き方は Claude に任せる

「必ず守っていること」（7章）だけを、スクリプトのコード・hooks・Claude Code の許可の設定（会社のフォルダの `.claude/settings.json`）で止め、ほかはできるだけ Claude の判断に任せています。モデルが進むほど、細かい指定は、かえって書く力を縛るためです。

2026年11月7日に、計画書の書き手と審査役に渡していた決まりを洗い出し、「守るもの」と「書き方を縛っているだけのもの」に分けました。

- **守るもの**：事実を作らない、本文の数字に出典を付けて財務モデルと合わせる、様式の項目と欄を書く、上限を超えない。これらは、コードの確かめと審査役で守り続けます。
- **任せたもの**：段落ごとの事実の並べ方、書き出しや文の長さ、図を置く場所の目安、文体の基準を型として当てはめること。これらの指示はやめ、書く目的と審査の観点だけを渡して、書き方は Claude に任せました。
- **分量**：公募要領に上限や目安がある所はそれを守ります。ない所は字数を決めず、審査役が読んで「足りない」「長すぎる」を判断します。
- **制度ごとの知見**：その制度で書くときだけ渡し、ほかの制度の計画書に混ぜません。

直す前は、デモの会社の数値計画が書けず、計画書に【空欄】（書けなかった所の印）が9か所残って、審査役の確かめまで進めませんでした。直した後は、【空欄】0か所で書き切りました。このときの審査役の要修正11件は、すべて中身への指摘で、書き方の好みによるものは0件でした。そこから、要修正0件まで直しています。ただし、同じときに社長役（テストで社長の答えを返す AI）の答えも足したので、この差のすべてが、書き方の直しによるものではありません。

### 作るときも、Claude Code が中心

補助金の実務家である作者1人が、7日間で、Claude Code と一緒に作りました。

- 要件（[SPEC.md](SPEC.md)）、作り方（[docs/DESIGN.md](docs/DESIGN.md)）、タスクの一覧（[docs/TASKS.md](docs/TASKS.md)）を基準にし、タスクごとに作って、テスト番号で確かめました。
- 作り始める前と作りながら、仕組みが動くかを実験で確かめました（デスクトップアプリでの hook、会社のフォルダの設定、Word・Excel への書き込み、ブラウザの守り、eval の仕組みなど。[experiments/結果.md](experiments/結果.md)）。実験の結果で、画面入力のブラウザを、自作のものから Claude のブラウザに替えるなど、作り方を変えました。
- 開発用の Stop hook（`tests/dev_stop_hook.py`）が、Claude が応答を終えるたびに構成の検査と速いテストを流し、落ちたら直すまで続けさせました。主な変更では、開発用の subagent（`.claude/agents/spec-check.md`）で、変更を仕様と照らしました。
- 重ならない作業は、worktree の別のセッションで並べて進め、日ごとのブランチにまとめました。
- `claude plugin eval` で振る舞いを採点し、プラグインあり・なしの差を測りました。
- 期間中（2026年11月2日〜8日）のコミットは、マージを除いて350件を超えました。

## 5. 磨いた経過と、確かめたこと

### 主な試行錯誤

## 6. 確かめた補助金と、これから

- **確かめたのは2つです**：省力化と持続化です。テストの材料とデモには、省力化の第8回・第9回と、持続化の第20回の公募要領を使いました。
- **補助金を足しても、プログラムは変えない作りです**：1件目の省力化で作ったプログラムのまま、持続化の制度データを足すだけで、各段階のスクリプトが動くことを確かめました（T0-1）。持続化を足したコミットにプログラムの変更がないことは、`tests/test_T0_1.py` がコミットの件名（「B1a 持続化：」「B1b 持続化：」）で探して確かめます。そのため、これらのコミットはまとめたり件名を変えたりしません。
- **その前に直したのは1か所です**（コミット b6cae95、lib/kakunin.py）：様式の「書き込む位置をまだ対応づけていない」という注意が、画面に入力する持続化の様式にも出ていました。制度の名前ではなく、制度データにある様式の「入力先」（画面かファイルか）で分け、画面の様式には出さないようにしました。省力化の動きは変わりません。
- **ほかの補助金の申請書には、まだ使っていません**：公募要領から制度データを作れば、プログラムを変えずに動く作りですが、品質は確かめていません。AI モデルが進むのに合わせて、国のほかの補助金、都道府県・市区町村の補助金、厚生労働省の助成金に、どこまで対応できるかを、制度ごとに確かめていきます。

## 7. 必ず守っていること

Claude の判断に任せられない決まりだけを、スクリプトのコード、hooks、Claude Code の許可の設定（会社のフォルダの `.claude/settings.json`）で止めています。すり抜けたものは、結果の確かめ（ハッシュや書式の比較）で見つけて戻します（DESIGN 5章）。

- **提出ボタンを押さない**：「提出」「送信」「申請する」「確定」「完了」などを含むボタンは押させません。押してよいボタン（次へ・一時保存・戻るなど）だけを通します。
- **確認・誓約・同意のチェック欄に入れない**：これらの欄は担当者が入れます。hojokin が入れる欄（加点〈審査で点が足される取り組み〉の選択など）でも、名前が読み取れない欄には入れません。
- **パスワードを扱わない**：ログインは担当者がブラウザで行います。
- **添付するのは、決まった写しだけ**：申請書類のフォルダの「添付する書類」にある写しのうち、入力シートの添付する書類に当たるものだけです。
- **画面入力は、担当者が呼んだときだけ**：`/hojokin:nyuryoku` を呼んだ記録がないと、ブラウザのツールのクリック・入力・添付を止めます。
- **Word・Excel の様式と書式を壊さない**：書いてよい範囲だけに書き、範囲の外が1か所でも変わっていたら保存しません。その場のコードで書き換えた場合も、応答の終わりに比べて戻します。
- **原本と公式資料を変えない（変わったら戻す）**：読み取り専用にし、開いたときと応答の終わりに、置いたときのハッシュと照らします。変わっていたら版の履歴から戻し、社長に知らせます。
- **版のファイルを増やさない**：「_v2」「最終」「修正版」「コピー」などの名前のファイルを作らせません。
- **会社のフォルダの外を読まない・書かない**：ファイルのツールは、会社のフォルダの外（別の会社のフォルダや認証情報など）を読み書きしません。外の書類は、社長が場所を伝えたものだけを写して取り込みます。
- **書類と履歴を外に送らない**：会社のフォルダの版の履歴は、送り先を持ちません。
- **スクリプトが動かないときは止める**：Python が動かない、または時間内に終わらないときは、書き込み・Bash・ブラウザのツールを止めます（守りが気づかないうちに外れないように）。
- **会社のフォルダでないフォルダでは何もしない**：hooks は何も止めず何も書かず、スクリプトも、補助金を探すことと会社のフォルダを作ること以外は動きません。

### 守りが掛かる範囲

- hooks は、次のツールを使う前に見ます（`hooks/hooks.json`）：書き込み（Write・Edit・NotebookEdit）、Bash、読み取り（Read・Grep・Glob など）、ブラウザ（Claude のブラウザ・Claude in Chrome・computer-use）。
- ブラウザのツールは、名前に `Claude_Browser`・`claude-in-chrome`・`computer-use` が入るかで見分けます。`computer-use` を含む画面操作のツールは、会社のフォルダではすべて止めます。名前にこれらを含まないツール（たとえば、別の JavaScript を動かすツールや、ターミナルに打ち込むツール）でブラウザを操作したときは、この守りは掛からず、Claude Code の許可の確認に任せます。Claude のブラウザと Claude in Chrome の中での JavaScript の実行は止めています。
- Bash は、コマンドの中身を見ていません。止めるのは、スクリプト（Python）が動かないときだけです（`hooks/pre_tool_use.py`・`hooks/run.sh`）。会社のフォルダの中で Bash が変えたものは、応答の終わりの確かめ（原本と公式資料のハッシュ、様式の書式の比べ、版の名前のファイル）で見つけます。Bash で会社のフォルダの外を読み書きすることや、外へ送ること（curl など）は、hooks では見ていません。Claude Code の許可の確認に任せます。
- 「書類と履歴を外に送らない」は、版の履歴（Git）に送り先を持たせないことです。ブラウザの移動先（http・https はどこでも通す）、Web から取るときの行き先、Bash で送る先は、hooks では絞っていません。これらは、Claude Code とブラウザ側のサイトの許可に任せています（`lib/browser_guard.py`）。
- 「パスワードを扱わない」は、画面の欄の種類が password の欄と、名前に「パスワード」を含む欄に入れないことです。ほかの名前の欄（認証コード・暗証番号など）は見分けていないので、担当者が入れてください（`lib/browser_guard.py`）。
- 守りが相手にしているのは、協力的な Claude と、Git を知らない社長のうっかりです（DESIGN 5章）。書類や画面に書かれた文に Claude が乗せられる場合までは、止めきれません。

## 8. 入れ方と使い方

### 入れ方（Claude のデスクトップアプリ）

1. デスクトップアプリの「設定」→「プラグイン」→「＋ 追加」→「リポジトリから追加」を選びます。
2. このリポジトリ（GitHub の公開のリポジトリ）の場所を入れて、hojokin を足します。リポジトリのルートの `.claude-plugin/marketplace.json` が、ルートにあるプラグインを指しています。
   - 画面からは、手元のフォルダを足せません（実験 E4）。

ターミナルでは、次のコマンドで入ります（Claude Code 2.1.317 の `claude plugin install --help` に `--marketplace` があることは確かめました。このコマンドで実際に入れることは、期間中は確かめていません）。

```sh
claude plugin install hojokin --marketplace tetsuroikeda/hojokin-oss
```

### 使い方

1. 会社のフォルダにする、新しい空のフォルダを作ります（下の「初回の準備」と「使うときの注意」を先に読んでください）。
2. デスクトップアプリで、そのフォルダを開きます。モードは auto を選ぶよう勧めます（会社のフォルダの中の読み取りと編集が、確認なしになります）。
3. 「うちで使える補助金ってある？」のように、ふだんの言葉で話しかけます。どの段階の skill を使うかは、Claude が選びます。
4. 申請画面への入力だけは、担当者が `/hojokin:nyuryoku` を呼びます。「申請画面に入れて」と頼んでも、Claude は自分では始めず、このコマンドを案内します。

### 初回の準備

- **Mac の開発ツール**：スクリプトは、Mac に入っている `/usr/bin/python3` で動きます。開発ツールが入っていない Mac では、「ターミナル」で `xcode-select --install` を実行し、出てきた画面に従って入れてから、Claude を開き直してください。スクリプトが動かないときは、プラグインが書き込み・Bash・ブラウザのツールを止め、同じ案内を Claude に渡します。
- **ライブラリの準備は要りません**：使うライブラリ（版の履歴の dulwich、PDF を読む pypdf、Excel を作る openpyxl など）は、Python だけで書かれたものをプラグインに同梱しています（`lib/vendor/`）。初回の通信や pip の準備はありません。
- **LibreOffice（あれば）**：申請書の PDF の写しを作るときと、Excel の数式を計算し直すときに使います。入っていないときは、その操作を案内します。
- **Claude in Chrome（画面入力に勧めます）**：書類の添付まで hojokin が行えます。デスクトップアプリの内蔵ブラウザでは添付ができないので、添付は担当者が行います。ターミナルでは `/chrome` で有効にします。
- **会社のフォルダを作る**：どの skill も最初に、今のフォルダが会社のフォルダか（目印の `.hojokin/` があるか）を確かめ、なければ「このフォルダを〇〇社の会社のフォルダにしますか」と聞きます。了承すると、スクリプトが、目印、フォルダの形、版の履歴、`.claude/settings.json`（外を読み書きさせない設定と、書き換えを止める規則）を一度に用意します。
  - 次のフォルダは、会社のフォルダにしません：ホームのフォルダとそれを含むフォルダ、ディスクのルート、前から `.git`・`.gitignore`・`.claude/settings.json` があるフォルダ。そのときは、新しいフォルダを作って始め、元の書類は場所を伝えて取り込むよう案内します。

### 会社のフォルダの形

```
<会社のフォルダ>/
├─ 今の状態.html          まずこれを開く。進み具合の画面（見るだけ。開くたびに作り直す）
├─ 今の状態.xlsx          同じ内容の Excel
├─ 補助金の候補.docx       探した結果
├─ 財務モデル.xlsx         会社の数字の土台（前提と根拠、既存事業・新事業・合算）
├─ 入れ口/                書類をとりあえず入れるフォルダ（ほかの場所に入れてもよい）
├─ 原本/                  受け取った書類。読み取り専用。名前は「<日付>_<種類>_<相手先>.pdf」の形
├─ 案件/
│   └─ <年>_<制度>_<回>/
│       ├─ 概要と流れ.docx     制度の概要、要件と義務、手続きの流れと期限、必要書類
│       ├─ 公式資料/           公募要領・様式・手引き（読み取り専用）
│       ├─ 1_申請/
│       │   ├─ 申請書/         計画書、入力シート、根拠対照表
│       │   └─ 添付する書類/   原本から作った写し
│       └─ 2_交付申請/ … 4_効果報告/1年目/ …（制度データの手続きの段階から作る）
├─ 見るだけ/              前の版や提出版を見たいときだけ出す（開くたびに片付ける）
├─ 記録/                  hojokin が管理する（会社の記録、制度データ、書類の台帳、期限の台帳など）
├─ .hojokin/              会社のフォルダの目印と設定
├─ .claude/settings.json  初回に社長の了承を得て作る設定
└─ .git/                  版の履歴（送り先は持たない）
```

- 書類ごとに1つのファイルを直して使います。前の版と提出版は版の履歴に残り、「_v2」「最終」のような名前のファイルは作りません。

### 使うときの注意

- **会社のフォルダは、同期されないフォルダに作ってください。** iCloud Drive・Google ドライブ・OneDrive・Dropbox などで同期されるフォルダに置く形（版をファイルで残す形）は、期間中は選べません。
- **デスクトップアプリでは、会社のフォルダそのものを開いてください。** 目印（`.hojokin/`）は開いたフォルダだけで確かめ、親のフォルダはさかのぼりません。会社のフォルダを含む親のフォルダや、会社のフォルダの下のフォルダで開くと、会社のフォルダと見なされず、守りの hooks も働きません。
- **同じ会社のフォルダを、2つの Claude で同時に開かないでください。** 版の履歴や台帳への書き込みが、ぶつかることがあります。
- **本物の申請画面に入れる前に、制度ごとの規約と遵守事項を、担当者が確かめてください。** 持続化補助金の申請システムの操作手引きには、BOT などによる操作を禁じる定めがあります。本物の画面では、hojokin が作った入力シートを見ながら、担当者が自分で入れることを勧めます。
- 書類の作成者と申請者は、事業者自身です。hojokin は、事業者が自分で進めるための道具です。申請画面の支援者の欄には、「このツールは支援者には当たりません。人の支援者がいる場合は正直に書いてください」と案内します。
