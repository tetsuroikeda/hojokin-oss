# 会社の記録と版（F13 の一覧と手直し、版）

## 最初に目印を確かめる

- 最初に、今のフォルダに `.hojokin/`（会社のフォルダの目印）があるかを確かめる。
- 目印がなければ、ほかのことをせずに「このフォルダを〇〇社の会社のフォルダにしますか」と社長に聞く。
- 社長が了承したら、会社のフォルダを作る道具で用意してから進める。了承がなければ、何も書かずに終える。

## 版の扱い

目的は、社長が Git の操作を覚えなくても、書類の前の版を見たり戻したりでき、提出した申請書を後から同じ中身で取り出せること。

### 決まり

- 書類ごとに1つのファイルを直して使う。「_v2」「最終」「修正版」「コピー」のような名前の別ファイルは作らない（作ろうとすると止められる）。
- 版は hook が自動で残す。応答の終わりにツールが変えた分を「ツール」として、社長が送ったときと開いたときに社長が手で変えた分を「社長」として残す。Claude が版を残す操作をする必要はない。
- 社長には「版」「履歴」「提出版」の言葉で話す。「コミット」「Git」などの言葉や、Git の操作を求めない。
- 前の版や提出版は、`見るだけ/` に読み取り専用で出す。次に Claude を開いたときに片付く。作業のファイルは増えない。
  - `見るだけ/` のファイルを直したり、作業のファイルを `見るだけ/` に置いたりしない（版の履歴に入らず、片付けの対象になるため）。
  - 社長が `見るだけ/` に置いたものは、片付けでも消さずに残る。そう知らせが来たら、別の場所（書類なら `入れ口/`）に移すよう伝える。
- 原本・公式資料は、入れたときの1版だけを守る。戻す対象にしない。

### 道具

どれも、する事の後に `--folder "${CLAUDE_PROJECT_DIR}"` を付ける。書類は、会社のフォルダからの場所（例：`案件/2026_省力化（一般型）第9回/1_申請/申請書/その1.docx`）で指す。名前（`その1.docx`）だけでも、履歴の中で1つに決まればよい。

```bash
# 版の履歴（新しい順。0 が今の版、1 が1つ前）。日時・だれ・変更・理由・版の印が出る
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/versions.py" log --folder "${CLAUDE_PROJECT_DIR}" --document "<書類>"

# 前の版を 見るだけ/ に出す（--version は log に出た版の印。--back 1 は1つ前）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/versions.py" show --folder "${CLAUDE_PROJECT_DIR}" --document "<書類>" --version <版の印>

# 前の版に戻す（戻したことも、新しい版として残る）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/versions.py" revert --folder "${CLAUDE_PROJECT_DIR}" --document "<書類>" --version <版の印> --reason "<社長の発言>"

# 「提出した」ときに、提出版を記録する
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/versions.py" submit --folder "${CLAUDE_PROJECT_DIR}" --case "<案件>" --stage "<段階>" --reason "<社長の発言>"

# 記録した提出版の一覧と、提出版を 見るだけ/ に出す（--number を省けば最新）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/versions.py" submissions --folder "${CLAUDE_PROJECT_DIR}"
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/versions.py" show-submitted --folder "${CLAUDE_PROJECT_DIR}" --case "<案件>" --stage "<段階>" [--number <番号>]
```

- 終了コード2は、しなかったとき（書類・版・案件が見つからない、提出版を記録できないなど）。出力の理由を社長に平易に伝え、直せることなら直してから、もう一度流す。同じ呼び方で繰り返さない。
- 日時は道具の出力をそのまま使う（日本時間。自分で直さない）。

### 前の版を見る

- 「前の版を見せて」「先週の版はどうだった？」と言われたら、まず `log` で履歴を出し、日時・だれ（ツール・社長）・理由を社長に示す。
- どの版かが社長の言葉で1つに決まれば、`show --version` で出す。決まらなければ、履歴から2〜3件を挙げて聞く。
- 出したら、場所（`見るだけ/…`）と、読み取り専用で次に開いたときに片付くことを伝える。中身を説明するときは、今の版との違いを中心に示す。

### 戻す

- 「1つ前に戻して」「さっきの直しを取り消して」と言われたら、`log` で戻す先の版を確かめ、どの版（日時・だれ・理由）に戻すかを一言示してから、`revert --version` で戻す。`--reason` には社長の発言をそのまま渡す。
- 履歴のいちばん新しい版が提出版の記録（`記録/提出版.json`）のこともある（提出の直後など）。「1つ前に戻して」は、社長が直した書類（申請書など）を指すものとして、`log --document` でその書類の版から選ぶ。
- 戻した後は、戻したことも履歴に残ったこと、戻す前の版も取り出せることを伝える。
- 戻すのは書類（申請書、根拠対照表、会社の記録など）だけ。原本・公式資料・審査役の結果・提出版の記録（`記録/提出版.json`）・設定は戻せない。原本を差し替えたいときは、新しい原本を入れてもらう（shorui）。提出版の記録は、壊れたか消えたときだけ、直すために戻せる。

### 「提出した」と言われたとき

- 提出するのは担当者で、Claude は提出しない。ここで行うのは、提出した時点の申請書を「提出版」として残すことだけ。
- 「提出した」「申請を出した」「送信した」「出し直した」と言われたら、どの案件のどの段階（`1_申請`、`2_交付申請` など）かを確かめる。案件と段階が1つずつしかなければ、`--case` と `--stage` は省ける。迷うときは、理由を添えて1問だけ聞く。
- `submit` を流す。`--reason` には社長の発言をそのまま渡す。提出版には、段階のフォルダのすべて（申請書/ の計画書・入力シート、添付する書類/ の写し）と、財務モデル.xlsx が入る。まだ版になっていない変更は、先に版に残してから入れる。
- 段階のフォルダの中に、版の履歴に残せないもの（読めないファイルやフォルダ、.gitignore に当たるファイルなど）があると、道具は提出版を記録せずに、その場所とわけを挙げて断る。社長に場所を示し、読めるようにしてもらう（権限を直す）、.gitignore から外すなどしてから、もう一度 `submit` を流す。Word が開いている間だけできるファイル（`~$…`）や `.DS_Store` は書類でないので、残っていても断らない。
- 別名（シンボリックリンク）も断る。版の履歴には指す先の名前しか残らず、先の写しが提出版に入らないため。段階のフォルダの中の別名、財務モデル.xlsx の別名、段階のフォルダやその上のフォルダの別名のどれも断る。別名を消して、本物のファイルやフォルダ（写し）をそこに置いてもらってから、もう一度 `submit` を流す。`記録/` か `記録/提出版.json` が別名のときも、提出版の一覧を読まず書かずに断る（`submissions`・`show-submitted` も同じ）。別名の先が会社のフォルダの外のこともあるため。本物のフォルダやファイルに置き換えてもらってから、もう一度流す。
- 流した後、入れたファイルの一覧を社長に示し、画面で提出したものと同じかを確かめてもらう（違うファイルを出していたら、直してから出し直しとして記録する）。
- 出し直したとき（差し戻しの後など）も `submit` を流す。2回目として足され、前の提出版も残る。

### 提出版を見る

- 「提出したときの申請書を見せて」と言われたとき、差し戻しや実績報告で提出したものと照らすときは、`show-submitted` で `見るだけ/` に出す。道具が、中身が提出したときと同じことを印で確かめる。
- 提出済みの案件の数字は、提出版の財務モデル.xlsx で固定されている。照らすときは、今の財務モデルではなく提出版のものを使う。

## 会社の記録（覚えていること）

目的は、社長が一度答えたことを二度聞かず、次の申請書にすばやく生かすこと。記録は `記録/会社の記録.json` にあり、会社のフォルダごと移しても使える。学ぶのはこの会社のことだけ。

### 何を残すか

- 会社の事実（所在地、従業員数、設備、売上、強みなど）：社長の答え、社長の訂正、書類から分かったことを、出典と一緒に残す。
- 書き方の決まり（直した表現、好む言い方、避けたい言い方、書き方の方針、構成）：社長の指摘や手直しのうち、次からも守るもの。
- 「今回だけ」の指示は残さない。どちらとも取れるときは「次からもそうしますか」と確かめてから残す。
- 推測や、Claude が考えた案は残さない。残すのは、社長の言葉と書類に書かれたことだけ。

### 道具

どれも、する事の後に `--folder "${CLAUDE_PROJECT_DIR}"` を付ける。覚えた日・答えた日は、省けば今日の日付（差し替えを含む）になる。

```bash
# 事実を足す（--changeable は従業員数・売上・給与・最低賃金など変わりうる情報、--fixed は設立の日・法人番号など）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/record.py" add-fact --folder "${CLAUDE_PROJECT_DIR}" --name "<名前>" --value "<値>" --changeable --source 質問 --question "<聞いた質問>"
#   出典が書類のとき：--source 原本 --file "<会社のフォルダの中の場所>" [--page <ページ>]
#   出典が社長の発言のとき：--source 社長の発言 --utterance "<社長の発言をそのまま>"
#   出典が社長の手直しのとき：--source 社長の手直し --file "<直した書類>"

# 書き方の決まりを足す（--kind は 直した表現・好む言い方・避けたい言い方・書き方の方針・構成）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/record.py" add-rule --folder "${CLAUDE_PROJECT_DIR}" --kind 避けたい言い方 --content "<内容>" --trigger "<社長の発言や手直し>" --source 社長の発言 --utterance "<社長の発言>" [--case "<案件>"]

# 記録のままでよいと社長が確かめた（最後に確かめた日を今日にする）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/record.py" confirm --folder "${CLAUDE_PROJECT_DIR}" --id <事実の id>

# 社長が決めた新しい値にする
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/record.py" update-fact --folder "${CLAUDE_PROJECT_DIR}" --id <事実の id> --value "<新しい値>" --source 社長の発言 --utterance "<社長の発言>"

# 覚えていることの一覧（何を、いつ、どこから）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/kiroku/scripts/record.py" list --folder "${CLAUDE_PROJECT_DIR}"
```

- 名前は、社長が見て分かる短い言葉にする（例：「従業員の数」「いちばん低い時給」）。同じことには同じ名前を使う（道具は、同じ名前の事実を同じものとして比べる）。
- 値は、社長の答えや書類の言葉をそのまま書く。単位と、何を含むか（「役員は入れない」など）も書く。
- 出典の書類は、会社のフォルダの中の場所で指す。外のファイルは、取り込みの道具で写してから指す。
- 終了コード2は、しなかったとき（引数が足りない、出典の書類がない、記録が読めない、食い違いなど）。記録は変わっていない。理由を読み、直せることなら直してから、もう一度流す。同じ呼び方で繰り返さない。
- 版は応答の終わりに hook が自動で残す。前の値は版の履歴から見られ、戻せる（上の「版の扱い」）。

### 食い違ったとき

- `add-fact` で、同じ名前の事実が違う値で記録にあると、道具は上書きせずに終了コード2で両方を出典付きで出す。
- 両方を出典付きで社長に示し、どちらが正しいかを決めてもらう。社長が新しい値に決めたら `update-fact`、記録のままでよければ `confirm` を流す。決めてもらうまで、どちらの値でも書かない。

### 一覧と、社長が直すとき

- 「この会社について何を覚えているか見せて」と言われたら、`list` を流し、何を・いつ・どこから覚えたかを示す。
- 社長が「記録の◯◯を直して」と言ったら、`update-fact` で直す。社長が `記録/会社の記録.json` を手で直してもよい。直した内容は次から使う。
- 開いたときに「会社の記録を使えません」と伝えられたら（社長の手直しで形が崩れたときなど）、理由を社長に平易に伝え、版の道具で前の版に戻すか、直してもらう。
