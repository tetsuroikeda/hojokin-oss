# 電子申請の入力（F10 の画面入力）

目的は、入力シート.xlsx の値を申請画面に入れ、一時保存まで進めること。入れた後は画面を読み直して入力シートと照らし、ツールが入れた欄と担当者が入れる欄を一覧で示す（SPEC F10・2.3、DESIGN 5章）。手順は固定する。順番を変えない。

## してはいけないこと（画面入力の守りの hook も止める）

- 「提出」「送信」「申請する」「確定」「完了」を名前に含むボタンは押さない。制度データの「押してよいボタン」（次へ・一時保存・戻るなど）だけを押す。
- 確認・誓約・同意・宣誓のチェック欄（名前にこの語がない宣誓の行も）には入れない。担当者が入れる。
- パスワードの欄には入れない。ログイン（GビズID など）は担当者が自分で行う。
- 画面を操作する機能（computer use）、座標でのクリック、ダブルクリック・右クリック・ドラッグ、打ち込み（type）、Enter などのキー、JavaScript とショートカットは使わない。欄には form_input で入れ、ボタンは番号（ref）で指してクリックする。
- 守りに拒まれたら、別の道具や書き方で通そうとしない。理由を担当者に伝え、担当者に画面で操作してもらう。
- その場の計算のコードが要るときは、Write で `記録/一時/` に置く。`python3 -c`・パイプ・sed は使わない（会社のフォルダの設定で、確かめの画面が出るため）。

## 1. 始める前に確かめる

1. 今のフォルダに `.hojokin/`（会社のフォルダの目印）があるかを確かめる。なければ画面には触れず、「このフォルダを〇〇社の会社のフォルダにしますか」と担当者に聞く。
2. 入力シートを確かめる。

   ```bash
   python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/nyuryoku/scripts/nyuryoku.py" sheet --folder "${CLAUDE_PROJECT_DIR}"
   ```

   - 入力シートがない（終了コード2）ときは、kaku で入力シートを作ってから始める。
   - 文字数の上限を超える値や、チェック欄の値の書き方が分からない行がある（終了コード4）ときは、画面に入れる前に kaku の `yoshiki.py sheet` で直す。上限を超える値は画面に入れない。
   - 案件が2つ以上なら `--case`、段階を指すなら `--stage` を付ける（下の道具も同じ）。
3. ブラウザを決める。Claude in Chrome を勧める（添付までできる）。内蔵ブラウザのときは、添付は担当者に頼む（内蔵ブラウザはファイルを選べない。実験 E1）。
4. 申請サイトを開き、ログインの画面で止まる。「ログインは担当者さんが自分でしてください。パスワードは私は扱いません」と伝え、ログインが済んだと言われてから続ける。

## 2. 画面ごとに入れる（1画面ずつ）

1. ページを読む（read_page。filter は all）。部品の番号は画面ごとに振り直されるので、クリックやページの移動の後は、必ず読み直してから操作する。
2. 入れる欄の一覧を出す。`--screen` には入力シートの「画面」の名前を渡す。

   ```bash
   python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/nyuryoku/scripts/nyuryoku.py" list --screen "加点項目" --folder "${CLAUDE_PROJECT_DIR}"
   ```

   - 道具は、hook が控えた最後の読み取りを使う。hook が動いていないときは、read_page の結果を `--page -` で標準入力から渡す。
   - 出た「部品の番号」と「form_input の値」のとおりに、form_input で入れる。チェック欄は true（入れる）・false（外す）、ラジオボタンは選ぶ項目の番号に true を渡す。まとめて動かす道具（browser_batch）を使うときは、入力だけを並べ、クリックは入れない。
   - 「入力シートにあって、画面に見当たらない」「同じ名前の欄が2つ以上ある」が出たら、その欄は入れずに担当者に伝える。
   - 「担当者が入れる」欄（確認・誓約・同意・宣誓、名前の読めない欄など）は入れない。最初の誓約や宣誓の画面のように、担当者が入れる欄しかない画面では、入れるべき欄を示して止まり、担当者が入れて「次へ」を押してから続ける。
3. 入れた後に、もう一度ページを読み、入力シートと照らす。

   ```bash
   python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/nyuryoku/scripts/nyuryoku.py" check --screen "加点項目" --folder "${CLAUDE_PROJECT_DIR}"
   ```

   - 「合わない」「画面に見当たらない」がある（終了コード4）ときは、その欄を入れ直してから、もう一度読んで照らす。2回直しても合わなければ、担当者に伝える。
   - チェック欄とラジオボタンは、入れた後の状態をページの構造から読み取れない（実験 E1）。道具が出した「担当者に画面で確かめてもらう」一覧を担当者に示し、画面で確かめてもらってから続ける。
4. 添付の欄があるとき（Claude in Chrome）：file_upload で、案件の段階のフォルダの `添付する書類/` にある写しのうち、入力シートの添付の欄に書いた書類の写しだけを添付する（原本は添付しない。守りも、入力シートにない写しは止める）。添付の後はページを読み直し、ファイルの名前が入ったことを確かめる。内蔵ブラウザのときは、添付する書類の場所と欄を担当者に示し、添付してもらう。
5. 「一時保存」を番号で指してクリックする。押した後はページを読み直し、保存できたこと（知らせの文など）を確かめる。
6. 次の画面へ進むときは「次へ」を番号で指してクリックし、1 に戻る。

## 3. 終わり方

- 最後の確認の画面まで来たら、そこで止まる。「提出」は押さない。
- 担当者に次の一覧を示す。
  - ツールが入れて、一時保存した画面と欄
  - 担当者に画面で確かめてもらうチェック欄・ラジオボタン
  - 担当者が入れる欄（確認・誓約・同意・宣誓のチェック欄など）
  - 添付してもらう書類（内蔵ブラウザのとき）
- 「確認・誓約・同意の欄を担当者さんが入れ、画面の内容を確かめてから、担当者さんが『提出』を押してください」と伝える。
- 支援者の欄（「事業計画書作成支援者」など）があれば、「このツールは支援者には当たりません。人の支援者がいる場合は正直に書いてください」と案内する（SPEC 2.3）。

## 道具の終了コード

- 0：照らした値がすべて合う（sheet・list は、入れられない値がない）
- 2：しなかった（会社のフォルダでない、入力シートや画面の控えがない、画面の名前が入力シートにない など）。出た文のとおりに準備してから流し直す
- 4：合わない値・画面に見当たらない欄・上限を超える値・書き方の分からない値がある
- 1：補助プログラムを読み込めない。プラグインの入れ直しを案内する
