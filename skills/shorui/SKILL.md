# 書類の整理と不備チェック（F5）

## 最初に目印を確かめる

- 最初に、今のフォルダに `.hojokin/`（会社のフォルダの目印）があるかを確かめる。
- 目印がなければ、ほかのことをせずに「このフォルダを〇〇社の会社のフォルダにしますか」と社長に聞く。
- 社長が了承したら、会社のフォルダを作る道具で用意してから進める。了承がなければ、何も書かずに終える。
- 道具に渡す JSON とその場の計算のコードは、Write で `記録/一時/` に置いて渡す。標準入力（`<<'EOF'`）・`python3 -c`・パイプ・sed は使わない（会社のフォルダの設定で、確かめの画面が出るため）。
- 道具は、下に書いた形のまま1回に1つずつ動かす。変数（`F=…`）・`for`・`&&`・`;`・`2>/dev/null` でつながない（skill の許可の形から外れ、確かめの画面が出るため）。

## 書類の整理

目的は、社長が会社のフォルダのどこに入れた書類も、原本の置き場に決まった形の名前で1つずつそろい、どの書類がどこから来たかを後からたどれること。中身は1バイトも変えない。

### 決まり

- 書類を見つける・移す・名前を付ける・台帳に残すのは、道具だけが行う。Bash の `mv`・`cp` や、ファイルの道具で、原本の置き場（`原本/`）と公式資料（`案件/<案件>/公式資料/`）のファイルを動かしたり、書き換えたりしない。
- 原本と公式資料は読み取り専用。開いたときと応答の終わりに、入れたときの中身と照らされ、変わっていれば戻される。そう知らせが来たら、社長に平易に伝える。直した形が要るときは、原本はそのままにして写しを作る。
- 台帳（`記録/書類の台帳.json`）の原本の場所・ハッシュ・版の印は書き換えない。台帳から項目が消えても、書き換えても、照らしは入れたときの値で続き、そのことが知らされる。
- 何の書類か（種類・日付・相手先・区分）は、中身を読んで決める。ファイルの名前だけで決めない。推測で埋めない。
- 何の書類か、どの案件で使うかが分からないものは、動かさずに社長に聞く。聞くときは理由を一言添え、一度に3つまでにする。
- 同じ中身の書類は、動かさずに知らせ、1つにまとめるかを社長に確かめる。道具は書類を消さない。
- 会社のフォルダの外（デスクトップ、ダウンロードなど）の書類には触れない。社長が場所を伝えたら、取り込んでから整理する。

### 道具

どれも、する事の後に `--folder "${CLAUDE_PROJECT_DIR}"` を付ける。場所は、会社のフォルダからの場所（例：`入れ口/scan0001.pdf`）で渡す。

```bash
# 新しい書類を見つける（会社のフォルダのどこにあっても。原本の置き場の台帳にあるものと、ツールの置き場は除く）。結果は JSON
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/seiri.py" scan --folder "${CLAUDE_PROJECT_DIR}"

# Word・Excel・PDF の文字を出す（写真と、文字のない PDF は Read で開く）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/seiri.py" text --folder "${CLAUDE_PROJECT_DIR}" --path "<場所>"

# 1つの書類を原本の置き場へ移し、決まった形の名前にして台帳に残す
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/seiri.py" organize --folder "${CLAUDE_PROJECT_DIR}" --path "<場所>" --category "<区分>" --kind "<種類>" --date "<日付>" --partner "<相手先>"

# 動かさずに確かめた書類として台帳に残す（社長が「そのままでいい」と答えたもの など）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/seiri.py" keep --folder "${CLAUDE_PROJECT_DIR}" --path "<場所>" --reason "<社長の答え>"

# 台帳の原本の一覧
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/seiri.py" list --folder "${CLAUDE_PROJECT_DIR}"
```

- 終了コード2は、しなかったとき（同じ名前・同じ中身の原本がある、日付の形が違う、会社のフォルダの外 など）。出力の理由を読んで直せることなら直し、もう一度流す。同じ呼び方で繰り返さない。書類も台帳も変わっていない。
- 「原本」「原本/<区分>」「記録」「記録/書類の台帳.json」が別名（シンボリックリンク）になっていると出たら、別名の先は会社のフォルダの外のこともあるので、その場のコードで移したり台帳を書いたりしない。場所を社長に伝え、本物のフォルダやファイルに置き換えてもらってから、もう一度流す。
- 「書類の台帳.json がありません」「読めません」と出たら、台帳を直してから整理する。消えた・壊れたときは、kiroku の版の道具（`revert`）で `記録/書類の台帳.json` を前の版に戻す。社長が手で直していた途中なら、社長に確かめる。台帳を作り直したり、空の台帳を書いたりしない。
- 終了コード1は、補助プログラムが読み込めないとき。社長に伝える。

### 開いたとき（前回から増えた・変わった書類）

- 開いたときの情報に「前回から増えた・変わった書類」があれば、社長の最初の発言のときに、その書類だけを整理し、不備を確かめる。社長が別のことを頼んだら、そちらを先にする。
- `scan` の結果の「前回から」で見分ける。「増えた」「変わった」は開いたときに見つけたもの、「開いた後に入れた」はこの会話の途中で入ったもの、「前からある」は前回からあって整理していないもの。
- 「前からある」書類は、社長に「整理して」と頼まれたときだけ整理する。頼まれていなければ、件数だけ伝える。「開いた後に入れた」書類は、「確認して」「整理して」と頼まれたら整理する。
- 中身のハッシュで比べているので、動かしただけ・名前を変えただけの書類は「増えた」「変わった」に入らない。それらには触れない。

### 流れ

1. `scan` で新しい書類を見つける。「新しい書類」が整理するもの、「同じ中身」が知らせて聞くもの。上の「開いたとき」の決まりで、今回整理するものを選ぶ。
2. 新しい書類を1つずつ読む。PDF と写真は Read で開く。Word・Excel は `text` で文字を出す。4件以上あるときは、読み取り役（yomitori）に `model: haiku` で仕分けを頼む（種類・日付・相手先・区分の読み取り。返す形は下）。読み取り役が「要確認」と返したものと、迷うものは、自分で開いて確かめる。
3. 書類ごとに、次を決める。
   - 区分：登記・名簿／決算・税／見積・契約・請求／役所からの通知／会社の資料／写真・カタログ のどれか。
   - 種類：書類の表題の言葉（見積書、請求書、決算書、履歴事項全部証明書、納税証明書（その2）、労働者名簿、議事録 など）。
   - 日付：書類にある日付。発行日・見積日・作成日・「〇月〇日現在」の日を使う。決算書は事業年度の始めの日。年だけの書類（カタログの「2026年版」など）は年だけにする。和暦は西暦に直す。
   - 相手先：見積書・請求書・カタログなど、外の会社が出した書類のその会社の名前（「株式会社」「有限会社」は省く）。役所が出した証明書と、自社で作った書類には付けない。
4. 決まったものから `organize` で移す。同じ名前の原本があると止まったら、見分ける言葉（機械の名前など）を `--note` に入れて動かし直す。
5. 分からないもの（表題・日付・相手先がなく、何の書類か、どの案件で使うかが読み取れないもの）は動かさずに社長に聞く。社長が「そのままでいい」「分からない」と答えたら `keep` で残す（次から聞き直さない）。
6. 終わったら、社長に一覧で知らせる：動かしたものは1行に1件、「元の場所 → 新しい場所」の形で（`organize` の出力の「元の場所」「新しい場所」）。動かさずに聞いたものは場所と聞く理由を、同じ中身のものは2つの場所を並べて、まとめるかを聞く。
7. 整理した書類が、外部に頼んでいた書類（開いたときの「外部への依頼と待ち」にあるもの）なら、junbi の skill を呼び、期限の道具の `--received "<書類>=<新しい場所>"` で、依頼の状態を「届いた」にする。

読み取り役に仕分けを頼むときの返す形（書類ごとに1つ）：

```json
{"書類": [{"場所": "入れ口/scan0001.pdf", "種類": "履歴事項全部証明書", "日付": "2026-10-22", "日付の種類": "発行日",
           "相手先": "", "区分": "登記・名簿", "状態": "確認済み", "メモ": ""}]}
```

- 読めない値は空にし、「状態」を「要確認」にして、メモに理由を書く。推測で埋めない。

## 見積書・請求書・納品書の金額の照合

目的は、金額と明細を正しく読み、計算で確かめ、確かめられない数字を推測で埋めずに社長に確かめること（SPEC F5、DESIGN 8.4）。
照合を通った見積書の金額だけが、経費明細に使える。

```bash
# 文字のない PDF と写真を、ページの画像にする（記録/一時/画像/ に置く）。上下が逆なら --rotate 180、拡大して読み直すなら --band
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/kingaku.py" image --folder "${CLAUDE_PROJECT_DIR}" --path "<原本の場所>" --rotate 180 --band 0.55,0.75

# 読み取り役が返した JSON（Write で 記録/一時/読み取り.json に置く）を、計算で照合して記録する
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/kingaku.py" check --folder "${CLAUDE_PROJECT_DIR}" --path "<原本の場所>" --input 記録/一時/読み取り.json --model sonnet --round 1

# 社長が確かめた値を入れて、照合し直す
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/kingaku.py" confirm --folder "${CLAUDE_PROJECT_DIR}" --path "<原本の場所>" --field "明細7.単価" --value "<社長の答え>"

# 記録した読み取りと照合の結果
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/kingaku.py" show --folder "${CLAUDE_PROJECT_DIR}"
```

1. 先に、上の流れで原本の置き場へ移す（照合は原本に対して行う）。
2. 書類ごとに、文字の入った PDF は `seiri.py text` で文字を出す。文字のない PDF と写真は `image` で画像にし、Read で開いて向きを見る。上下が逆・横向きなら `--rotate` で直した画像を作り直す。
3. 読み取り役（yomitori）に `model: sonnet` で、金額と明細を読ませる。渡すのは、原本の場所、画像の場所、yomitori の「見積書・請求書・納品書の金額と明細を読む」の形で返すこと。何通もあるときは1回でまとめて頼み、書類ごとの JSON を返してもらう。
4. 書類ごとに、返った JSON を Write で `記録/一時/読み取り.json` に置き（上書きする）、`check` で照合する。「状態」と「次にすること」のとおりに進める。
   - 「照合済み」：その書類は済み。
   - 「読み直す」：外れた明細のあたりを `image --band` で切り出して拡大し、読み取り役に `model: opus` で書類の全体を読み直させ、`check --round 2 --model opus` で照合する。
   - 「要確認」：推測で埋めない。読めない・合わない欄ごとに、切り出した画像の場所と読み取った数字を並べて、社長に確かめる（ほかの数から計算で出る値は「候補」として示してよいが、記録には入れない）。社長が答えたら `confirm` で入れる。
5. 終わったら、書類ごとに、合計と状態（照合済み・社長に確かめること）を社長に一覧で知らせる。

## 不備チェック

目的は、書類ごとの不備と書類どうしの食い違いを、見逃さずに重さ（重大・要確認・助言）と直し方を付けて示し、今の状態の画面の不備の数に出すこと（SPEC F5）。見逃しを減らすことを優先し、迷うものは「要確認」にする。

```bash
# 物差し：不備の型、この段階で集める書類の決まり（期数・有効期限）、対象にならない経費、過去の差し戻しの型、今日、交付決定の日
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/fubi.py" rules --folder "${CLAUDE_PROJECT_DIR}" --case "<案件>" --stage 1_申請

# 書類から読み取った項目（Write で 記録/一時/書類の読み取り.json に置く）を、コードで照らす。不備の候補が出る（何も書かない）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/fubi.py" check --folder "${CLAUDE_PROJECT_DIR}" --case "<案件>" --input 記録/一時/書類の読み取り.json

# 不備の一覧（Write で 記録/一時/不備.json に置く）を残し、今の状態の画面を作り直す
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/fubi.py" record --folder "${CLAUDE_PROJECT_DIR}" --case "<案件>" --input 記録/一時/不備.json
```

1. 先に、上の流れで書類を原本の置き場へ移す。見積書・請求書・納品書は、上の「金額の照合」まで済ませる。
2. `rules` で物差しを出す。
3. 書類ごとに、次の項目を読み取り、`記録/一時/書類の読み取り.json` に置いて `check` で照らす（書類にない項目は書かない）。
   `{"書類": [{"原本": "<原本の場所>", "種類": "履歴事項全部証明書", "制度データの書類": "<rules の書類の名前>", "発行日": "2026-10-22", "有効期限": null, "期": ["第17期", "第18期"], "社名": "…", "所在地": "…", "代表者": "…", "宛名": null, "従業員数": 15, "発注日": null, "契約日": null, "補助事業の経費": null}]}`
   - 期：決算書・納税証明書などが含む期（納税証明書は、載っている年度・期をすべて）。社名・所在地・代表者：書類にあるとおり（見積書は、宛名を「宛名」に）。従業員数：名簿の人数、概況説明書の従業員数。発注日・契約日：注文書・契約書の日付。補助事業の経費：補助事業で買うものの発注・契約なら true、今の事業の仕入れなら false。
4. コードの候補に、読んで判断する不備を足す。`rules` の不備の型の「確かめること」を、書類ごと・書類どうしで1つずつ確かめる。とくに次は見落とさない。
   - 経費の控え・メモの金額と、見積書の金額の食い違い。税込と税抜の混在。50万円以上の設備に見積書・カタログがない。
   - 補助の対象にならない経費（`rules` の「補助の対象にならない経費」に照らし、名前と資料のページを「出典」に書く）。見積書の明細の中の対象外の費目も見る。
   - 図面・カタログと見積書の食い違い（型番・台数）。過去の差し戻しの型に当たるもの。
5. まだ集めていない書類は、不備ではなく「まだない書類」に入れる（重さを付けない）。様式で作る書類（事業計画書、指定様式の名簿など）は、これから道具で作るので、不備にしない。条件付きの書類は、その条件に当たるか分からなければ、まだない書類に「当たるか確かめる」と書く。
6. 指摘を `記録/一時/不備.json` に置き、`record` で残す。形：`{"確かめた書類": ["<原本の場所>", …], "まだない書類": [{"名前": "…", "区分": "必須", "メモ": "…"}], "不備": [{"重さ": "重大", "種類": "<何が不備か。短く>", "書類": "<書類の名前と原本の場所>", "内容": "<読み取った値と、正しい値・食い違う相手>", "直し方": "<社長がすること>", "型": "不備-01", "出典": "<資料とページ>"}]}`。値はどれも文字にする（入れ子にしない）。
   - 重さは、不備の型の重さを使う。SPEC で重大と決まっているもの（期限切れ、期数不足、金額の不一致、名義の不一致、事前着手）は必ず重大。迷うものは要確認。
7. 社長には、重さごとに（重大から）、書類・何が不備か・直し方を一覧で示す。今の状態の画面の不備の数が変わったことも伝える。

## 外の書類の取り込み

- 社長が会社のフォルダの外（デスクトップ、ダウンロードなど）の書類を使いたいときは、場所を伝えてもらう（ファイルをこの画面に引いて入れるか、場所を書くか、「デスクトップに置いた」のように言ってもらう）。社長が送ったときに、発言にある外の場所が控えられる。
- 取り込みの道具は、社長の直前の発言にあった場所だけを、番号で受け付ける。コマンドに外の場所を書かない。外の場所を Read で開かない。

```bash
# 社長が伝えた外の場所を、番号つきで出す（フォルダなら、すぐ下のファイルの名前も）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/torikomi.py" list --folder "${CLAUDE_PROJECT_DIR}"

# その場所の書類を 入れ口/取り込み/<今日>/ に写す（元のファイルは変えない）。フォルダの中の1つだけなら --name
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/torikomi.py" import --folder "${CLAUDE_PROJECT_DIR}" --number <番号> --name "<ファイルの名前>"
```

- 取り込んだら、ほかの書類と同じく、上の流れで整理する。
- 「場所がありません」と出たら、社長に場所を伝え直してもらう。伝えていない場所から取り込もうとしない。

## 写しを作る（案件で使う書類）

目的は、案件ごとに、制度データの「提出するファイルの決まり」と書類の「形式」に合った写しが、段階の `添付する書類/` にそろい、どの原本から作ったかを後からたどれること。原本は変えない。

```bash
# 原本から写しを作る（2つ以上の原本を1つにつなぐときは --original を2回以上）。--document は制度データの書類の名前
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/utsushi.py" make --folder "${CLAUDE_PROJECT_DIR}" --original "<原本の場所>" --case "<案件>" --stage "1_申請" --document "<書類の名前>"

# 古い原本から作った写し（同じ種類の新しい原本が入ったもの）を、案件ごとに出す
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/utsushi.py" stale --folder "${CLAUDE_PROJECT_DIR}"

# 写しを、新しくなった原本で作り直す（同じ場所・同じ名前。古い原本は消さない）
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/utsushi.py" remake --folder "${CLAUDE_PROJECT_DIR}" --copy "<写しの場所>"

# 写しの一覧
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/shorui/scripts/utsushi.py" list --folder "${CLAUDE_PROJECT_DIR}"
```

- 写しは、道具だけが作る。Bash の `cp` や、その場のコードで作らない。PDF にする・つなぐ・容量を照らすのは道具が行う。
- 出力の「注意」（容量の上限を超える、名前の決まりがある など）は、社長に伝える。
- 原本を整理した（`organize`）出力に「新しくなった原本」があれば、古い原本から作った写しがある案件を社長に知らせ、`remake` で作り直す。古い原本は消さない（提出版と照らし合わせるため）。作り直したら、どの案件のどの写しを作り直したかを一覧で知らせる。
