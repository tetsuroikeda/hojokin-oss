# 案件の準備と、制度の質問・期限・改訂（F3、F4、F6、F7、F12 の手続きの切り替え）

## 最初に目印を確かめる

- 最初に、今のフォルダに `.hojokin/`（会社のフォルダの目印）があるかを確かめる。
- 目印がなければ、ほかのことをせずに「このフォルダを〇〇社の会社のフォルダにしますか」と社長に聞く。
- 社長が了承したら、会社のフォルダを作る道具で用意してから進める。了承がなければ、何も書かずに終える。

## 公式資料を取り、書類フォルダを作る（F3）

申請する制度と回が決まったら、最初に公式資料を取る。取るのも、置くのも、文字にするのも道具が行う。

1. 公式サイトのダウンロードのページで、公募要領・様式・手引き・電子申請マニュアル・スケジュールのページの場所を確かめる。
   申請する回の資料がまだ公表されていなければ、直近回の資料を使う（推測で次の回の場所を作らない）。
2. 取る資料の一覧を用意する。
   - 省力化（一般型）第8回と持続化（一般型・通常枠）第20回は、同梱の一覧がある：
     `${CLAUDE_PLUGIN_ROOT}/skills/junbi/取る資料/省力化_一般型_第8回.json`、`${CLAUDE_PLUGIN_ROOT}/skills/junbi/取る資料/持続化_通常枠_第20回.json`
   - ほかの制度は、同じ形で作る。「制度」に名前・略称・枠・種類（補助金か助成金）・公募回（申請する回）を、「資料」に資料ごとの id（短い呼び名。出典に使う）・名前・公募回（その資料そのものの回）・URL を書く。
3. 道具を動かす。申請する回が一覧の回と違うとき（第9回の申請を第8回の資料で始めるときなど）は、`--case-round` に申請する回を渡す。
   一覧を作ったときは、ファイルにせず `--list -` で標準入力から渡してよい。
   すでに始めた案件の資料を取り直すとき（公表された回の資料を取る、採択後の手引きを取る、改訂を確かめる など）は、
   前の `記録/資料の本文/<案件>/資料の一覧.json` の「案件」を `--case` に渡す。年が変わっていても、同じ案件のフォルダに置くため。
   `--case` を渡さなくても、同じ略称・枠・回の案件のフォルダが1つあれば、道具はそれを使う。

```
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/junbi/scripts/fetch_documents.py" --folder "${CLAUDE_PROJECT_DIR}" --list "${CLAUDE_PLUGIN_ROOT}/skills/junbi/取る資料/省力化_一般型_第8回.json" --case-round 第9回
```

4. 道具の結果を、社長に平易に伝える。
   - 「直近回である第◯回の資料に基づいています」と出たら、必ずそのまま伝える。回の違う資料（第6回版の手引きなど）も伝える。
   - 終了コード 1 は、そろっていない資料がある。取れなかった資料は、ダウンロードのページで場所を確かめ直して取り直す。「前と中身が違う」資料は、改訂かもしれないと社長に知らせる（道具は上書きしない）。
   - 終了コード 2 は、何もしていない（会社のフォルダでない、一覧の形が違う、案件のフォルダを決められない）。
     同じ制度・枠・回の案件のフォルダが2つ以上あると出たら、どの案件かを確かめて `--case` に渡して動かし直す。
5. 道具が作るもの
   - 書類フォルダ：`案件/<年>_<略称>（<枠>）<申請する回>/`（年は案件を始めた年）と、その中の `公式資料/`（読み取り専用。書き換えない）。段階のフォルダは、制度データを作った後に、その手続きの段階から作る。
   - ページごとの文字：`記録/資料の本文/<案件>/<資料の id>/`。`ページ_001.txt`（PDF のページごと。1行目に印刷されたページ番号）と `ページの対応.json`。出典は、いつも印刷されたページ番号で示す。文字のないページ（画像だけのページ）は、ページの対応の「文字を取り出せないページ」にある。
   - 資料の一覧：`記録/資料の本文/<案件>/資料の一覧.json`。制度データの「資料」と同じ形（id・名前・公募回・URL・取得日・ハッシュ・ページのずれ）で、制度データを作るときにそのまま使う。

## 制度データの下書きを、読み取り役に章ごとに読ませ、道具で裏取りする（F3）

公募要領は、本体では読み込まない（文脈を守るため）。読み取り役（subagent `hojokin:yomitori`）に章ごとに読ませ、返った JSON を道具で裏取りする。

1. 章を決める。公募要領の目次のページ（`記録/資料の本文/<案件>/<資料の id>/` のはじめの数ページ）を見て、章とページの範囲（印刷されたページ番号）を決める。一度に全部を読ませない。
2. その章で読む項目の形を、道具で出す（項目は制度データの項目の名前。いくつ並べてもよい）。

```
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/junbi/scripts/urakadori.py" --form 補助額 補助の対象になる経費
```

3. 読み取り役を呼ぶ。公募要領と様式を読ませるときは、モデルに **opus** を指定する（DESIGN 7章）。渡すのは、案件の名前、資料の id、章とページの範囲、読む項目、2. の形。
4. 返った JSON を、そのまま道具に渡す。

```
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/junbi/scripts/urakadori.py" --folder "${CLAUDE_PROJECT_DIR}" --case "<案件>" --input - <<'EOF'
（読み取り役が返した JSON）
EOF
```

5. 道具の結果で次を決める。
   - 終了コード 0：形が合い、どの値も裏取りで外れなかった。結果は `記録/制度データ/読み取り/<案件>/<章>_<回目>回目.json` にある。
   - 終了コード 1：裏取りで外れた値を「要確認」にした（理由は注記と結果の表にある）。外れた値のページだけを読み取り役にもう一度読ませ、根拠の文をページの文字のとおりに写させてから、もう一度通す。直らなければ、要確認のまま社長に示す。
   - 終了コード 2：何も書いていない。形が合わないときは、結果に出た誤りの一覧を読み取り役に渡し、返し直してもらう。
   - 推測で埋めない。読み取れない項目は空けたまま社長に伝え、問い合わせ文の案を作る（F3）。
