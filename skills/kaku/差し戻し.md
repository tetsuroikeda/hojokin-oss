# 差し戻しへの対応の進め方（SPEC F12・T12-2、DESIGN 4.5・10章。TASKS B32）

目的は、事務局からの差し戻しを、提出版（担当者が「提出した」と伝えた時点の申請書）と照らして箇所を特定し、直し方を示して直し、直した後に確かめ直すこと。差し戻しは、次からの書類集めで前もって注意できるよう、不備の型として会社の記録に残す。

## 1. 差し戻しを原本にする

- 社長が文面を貼り付けたときは、文面をそのまま Write で `入れ口/<受け取った日>_差し戻し.txt` に置き、shorui の整理で原本（`原本/役所からの通知/`）にする。画面の写真が入れ口などにあれば、それも同じく原本にする。中身は書き換えない。
- 写真は Read で開いて読む。読めない所は推測せず、社長に聞く。
- 差し戻しの文に出し直しの期限（「◯月◯日までに再提出」など）があれば、junbi の期限の道具で期限の台帳に残す
  （期限の台帳は道具だけが書く。開いたときの一覧と今の状態.html の近い締切に出る。11/7 の採択後の通しで、出し直しの期限が一覧に出なかった）。
  日付は文に書かれたとおりにする。書いていなければ、社長に聞くか、残さない（推測で入れない）。

```
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/junbi/scripts/kigen.py" --folder "${CLAUDE_PROJECT_DIR}" --case "<案件>" --due "差し戻しの出し直し=<YYYY-MM-DD>" --source "<差し戻しの原本の場所>"
```

## 2. 提出版と照らして、箇所を特定する

- この道具の `show` の「提出版の中身」を読み、差し戻しが指す所（画面の欄、経費の行、添付した書類）を探す。箇所は、ファイル・欄（行）・提出したときの値で示す。
- 正しい値は、原本（見積書・履歴事項全部証明書など）、財務モデル、提出版の計画書、会社の記録から取り、出典を添える。どこにもなければ社長に聞く（推測で直さない）。
- 差し戻しが複数の箇所を指すときは、全部を一覧にする。

## 3. 直す

- 直すのは、今の段階のフォルダ（`案件/<案件>/<段階>/`）の作業のファイル。新しいファイル（「_修正」「_v2」）は作らない。前の版は版の履歴に残る。
- Word・Excel の申請書は kaku の書き込みの道具で直す（Write・Edit で書き換えない）。文字のファイル（入力の控えの JSON など）は Edit で、その箇所だけを直す。
- 添付した書類が古い・期限切れのときは、新しい書類を社長に頼み（だれがいつ頼むかを junbi の依頼で残す）、届いたら shorui で原本にし、写しを作り直す。

## 4. 確かめ直す

- この道具の `diff` で、提出版から変わった所を出し、差し戻しが指す箇所だけが直り、ほかが変わっていないことを確かめる。
- 期限・名義・期数のある書類は、shorui の不備チェック（`check`）でも照らす。金額は、照合を通った見積書の金額と1円も違わないこと。
- 確かめた結果（直した箇所、前と後の値、出典、ほかに変わった所がないこと）を社長に示す。

## 5. 不備の型として残し、出し直す

- kiroku の `record.py add-defect` で、案件・段階・中身・原因・次に注意する書類・照合の決まり・差し戻しの原本・受け取った日を残す。照合の決まりは、次の書類集めでコードや目で照らせる形に書く（例：「見積書の有効期限が、出す日より後か」）。
- 担当者が出し直したら、kiroku の「提出した」で提出版を残す（2回目として足され、前の提出版も残る）。
  出し直しの期限を台帳に残していれば、`kigen.py --case "<案件>" --due "差し戻しの出し直し=済み"` で済みにする。
