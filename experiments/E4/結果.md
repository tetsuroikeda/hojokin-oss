# 実験 E4 の結果（2026-11-03）

デスクトップアプリの Code タブで、試しのプラグイン e4-probe の hook が動くかを確かめた。手順は `手順.md`、hook の作りは `e4-probe/hooks/`。

## 試し方

- 試しの会社 `~/hojokin-e4/試しの会社/`（目印 `.hojokin/` あり）と `~/hojokin-e4/目印なし/` に、CLI で local の範囲で入れた（`claude plugin marketplace add <experiments/E4> --scope local`、`claude plugin install e4-probe@hojokin-e4 --scope local`）。書かれたのは各フォルダの `.claude/settings.local.json` だけ。
- デスクトップアプリのセッションを3つ開いて流した（試しの会社で default モード、試しの会社で auto モード、目印なしで auto モード）。モデルは Sonnet 5.5。
- ログは `~/.hojokin-e4/hooks.jsonl`（場面ごと、17行）と `~/.hojokin-e4/sh.log`（起動用の sh）。

## 13.2 の手を取るか

取らない。SessionStart は動き、開いたときの情報も Claude に渡った。

## 骨組み（S3 など）に使うこと

- 拒むときは JSON（`permissionDecision: "deny"`）にする。終了コード2だと、理由の前に起動のコマンドの全文が付き、社長に見える文が読みにくくなる。
- hook が使う python3 は `/usr/bin/python3`（Python 3.9.6）だった。PATH には Homebrew などが入っていたが、社長の Mac では違うかもしれない（E5 で確かめる）。hook のコードは Python 3.9 で動く書き方にするか、run.sh で版を確かめる。
- `CLAUDE_PROJECT_DIR` に会社のフォルダが入る。目印の確かめに使える。
- 社長が入れているほかのプラグインも、開いたときに情報を渡す（目印なしのセッションでは、別のプラグインの案内文が渡っていた）。

## 残り（作者が見ること）

1. 「＋」→ Add plugins の画面で、手元のフォルダのマーケットプレイスを足して入れられるか。
2. セッションを開いて1分ほど待ってから送ったとき、SessionStart が開いたときに動くか、最初の発言のときに動くか。今回は開くと同時に発言を送ったので、見分けられなかった（SessionStart 15:19:28、最初の発言 15:19:31）。どちらでも Claude が動く前に情報は渡るので、作りは変わらない。
