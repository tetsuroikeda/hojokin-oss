# 実験 E5 の結果（2026-11-03）

確かめた項目は4つです。

1. uv と git を PATH から外した環境で、初回の準備が動くか
2. dulwich で版の管理が足りるか
3. LibreOffice か Word があるか
4. Python が動かないとき、hook が書き込みを止めるか

試しのコードはこのフォルダにあります。

| ファイル | すること |
|---|---|
| `setup_check.sh` | 1。venv を作り、ライブラリを入れる |
| `dulwich_check.py` | 2。dulwich で版の管理を試す |
| `make_docs.py` と `convert_check.sh` | 3。試しの Word・Excel を作り、PDF にする |

## 試し方

- **手元の環境は変えていない。** どの試しも、一時フォルダの中で `env -i` を使い、HOME・PATH などを試しの値にして流した。
- **「uv と git がない PATH」の作り方。** python3 だけを置いたフォルダに、`/bin`・`/usr/sbin`・`/sbin` を足した。
  - `/usr/bin` には git が、Homebrew と `~/.local/bin` には git・uv があるので、どれも外した。
- **「開発ツールがない」状態の作り方。** `DEVELOPER_DIR` を、ない場所にした。
  - こうすると、`/usr/bin/python3` と `/usr/bin/git`（どちらも xcrun の入口）がダイアログを出さず、すぐ終了コード1で終わる。
  - 返る文：「xcrun: error: missing DEVELOPER_DIR path」。
- **この Mac の状態。**
  - macOS 26.7（arm64）。開発ツールは Xcode.app にある。
  - `/usr/bin/python3` は Python 3.9.6（LibreSSL 2.8.3、pip 21.2.4）。
  - Claude Code は 2.1.317。
- **Claude Code の中での試し。** `claude -p` を `--plugin-dir`（このリポジトリ）で動かした。
  - 利用者の設定は読まない（`--setting-sources project`）。
  - モデルは Haiku。費用は3回で約 0.012 ドル。

## 13.2 の手を取るか

- **一部を取る。**
- **開発ツールが入っている Mac では、手は要らない。** 次のことが確かめられた。

  - 開いたときの案内は、run.sh が Python なしで出せる（SessionStart で、決まった文を出す）。中身と、そこまで作るかは作者が決める。

## 骨組み（S5 など）と DESIGN（S0）に使うこと

**準備の場所とやり方**

- 補助プログラムは、プラグインのデータの置き場（`CLAUDE_PLUGIN_DATA`）に venv を作って入れる。uv は使わない。
- hook と skill のスクリプトは、その venv の python3 があれば、それを使う。
  - 今の S3 の run.sh は、PATH の python3（標準のライブラリだけ）で動く。
  - dulwich などを hook で使うようになったら、run.sh が venv を先に探すよう直す。
- venv の python3 は、`/usr/bin/python3` の先（Xcode か開発ツールの中）への別名になる。
  - 開発ツールを更新して Python の版が変わると、venv を作り直す必要がある。
  - 初回の準備は「venv が動かなければ作り直す」形にする。
- 入れるライブラリの版は、決めて書いておく。
  - Python 3.9 は保守が終わっているので、今後のライブラリは 3.9 で入らなくなる。
  - urllib3 2.x は、LibreSSL で読み込むと警告を出す（`NotOpenSSLWarning`）。dulwich の通信の機能は使わないので、害はない。

**名前の文字**

- Finder などで作られた濁点の分かれた名前（NFD）を、dulwich はその形のまま履歴に残した。
- 書類を整理するスクリプトが原本の置き場に移すときは、名前を濁点の付いた1文字の形（NFC）にそろえる。

**PDF にする道具**

- LibreOffice は、`/Applications/LibreOffice.app/Contents/MacOS/soffice`（と `~/Applications`）、Spotlight の順に探す。PATH には頼らない。
- 利用者の設定は、一時フォルダにする（`-env:UserInstallation`）。社長が開いている LibreOffice とぶつからないように。

**Word で PDF にする（未確認）**

- Word を外から操作する許可（オートメーション）が要る。許可の設定が変わるので、ここでは試していない。
- E2a か、作者と一緒に確かめる。

## 作者が決めること（S3 の守りの強さ）

### (1) hook が時間切れになったとき（4b）

DESIGN 5章「補助プログラムが動かないときは止める」の行の、すり抜けへの備え「決まりが、気づかないうちに外れることを防ぐ」に関わります。

| 案 | 中身 |
|---|---|
| 案1（勧める） | run.sh に見張りを入れる。Python が hook の timeout より短い秒数（例：8秒）で終わらなければ止め、書き込みとブラウザの操作を拒む |
| 案2 | timeout を長くする（例：PreToolUse を60秒）だけ。固まったときに外れることは変わらない |
| 案3 | 今のまま。Stop hook の結果の確かめで見つけて戻す。ただし Stop も Python なので、固まると働かない |

### (2) Python が動かないとき、ページを読むだけのブラウザの道具も拒むか

spec-check の指摘です。DESIGN 5章「補助プログラムが動かないときは止める」と「画面入力は、担当者が呼んだときだけ」の行に関わります。

| 案 | 中身 |
|---|---|
| 案1（今の作り） | 名前に Claude_Browser・claude-in-chrome・computer-use を含む道具は、読むだけのものも拒む |
| 案2 | 読むだけの道具（read_page・get_page_text・find・screenshot など）は通す。名前を1つずつ並べて外す。知らない名前の道具は拒む |

Python が動かないと画面への入力は進められないので、案1のままでよいと考えます。

### (3) 書き込みに Bash を含めるか

今は Write・Edit・NotebookEdit だけを止め、Bash は止めていません。DESIGN 5章の「書き込み」は、ほかの所でも Write・Edit を指しているためです。含めるなら、hooks.json の matcher を1行直します。
