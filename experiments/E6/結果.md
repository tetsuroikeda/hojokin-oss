# 実験 E6 の結果（2026-11-03）

会社のフォルダの `.claude/settings.json`（DESIGN 4.7）が、デスクトップアプリの Code タブで効くかを確かめた。手順は `手順.md`、試しのプラグインは `e6-probe/`。

## 試し方

- 試しのフォルダはリポの外の `~/hojokin-e6/`（`make_folders.sh` で作った）。e6-probe は、会社A・会社B に CLI で local の範囲で入れた。
- デスクトップアプリのセッションを3つ開いて流した（試し1：会社A・default、試し2：会社A・auto、試し3：会社B・auto）。モデルは Sonnet 5.5。
- 版：デスクトップアプリの Claude Code は 2.1.309（`~/Library/Application Support/Claude/claude-code/` の最新）。ターミナルの CLI は 2.1.317。
- 記録は `~/.hojokin-e6/hooks.jsonl`（PreToolUse・PostToolUse・Stop）と、各セッションの報告。
- ユーザーの設定（`~/.claude/settings.json`）には、block の2つはない。そのため、拒否はどれも会社のフォルダの設定によるもの。

## 13.2 の手を取るか

取る（一部）。blockWrites はデスクトップアプリの今の版（2.1.309）では効かないので、「効かない決まりは、PreToolUse と Stop hook で補う」を取る。PreToolUse で、会社のフォルダの外への Write・Edit・NotebookEdit を拒む。その場で効くので、「開き直すよう案内する」は要らない。

## DESIGN（S0）と骨組みに関わること

1. **プラグインの補助ファイル（knowledge/、schema/ など）を、Claude が Read で読めない。** 案：(a) スクリプトが中身を出力して渡す（DESIGN 4.1 の「出力だけが文脈に入る」に合う）。(b) 会社のフォルダを作る道具が、プラグインの場所を作業フォルダに足す設定を書く（プラグインを更新すると場所が変わるおそれがある）。(c) 要るものを SKILL.md の本文に入れる。作者の判断が要る。
2. **ユーザーの設定にある追加の作業フォルダは、会社のフォルダのセッションでも読める。** この Mac では `/tmp`、別のプロジェクト、Google ドライブのフォルダが、拒否の文の「作業フォルダ」に並んだ。社長のパソコンで追加の作業フォルダがあると、そこは「外」にならない。会社のフォルダの設定で外せるかは、まだ確かめていない。
3. 外への書き込みは、PreToolUse で拒む（上の 13.2 の手）。デスクトップアプリが 2.1.314 以降になれば、設定だけで止まる。
4. Bash とその場のコードは、外の読み書きも原本の書き換えも、分類器が通すことがある。DESIGN 5章のとおり、原本は Stop hook の結果の確かめで戻す。これは効いた。
