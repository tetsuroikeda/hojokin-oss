# 実験 E6 の手順

DESIGN 13.2 の E6 を確かめます。会社のフォルダの `.claude/settings.json`（DESIGN 4.7）が Code タブで効くかを見ます。

## 用意

- `sh experiments/E6/make_folders.sh` で、リポの外の `~/hojokin-e6/` に試しのフォルダを作る（会社A：初めから設定あり、会社B：設定なし、外：外のファイル）。
- 会社A・会社B に、試しのプラグイン e6-probe を CLI で local の範囲で入れる（E4 で、画面からは手元のフォルダのマーケットプレイスを足せないと分かったため）。
- hook の記録は `~/.hojokin-e6/hooks.jsonl`。PreToolUse は、Claude が打ったコマンドの全文を残す。

## 試し（デスクトップアプリのセッションで流す）

| # | フォルダ・モード | すること | 見ること |
|---|---|---|---|
| 1 | 会社A・default | `/e6-probe:torikomi ~/hojokin-e6/外/外の資料.txt` | skill の allowed-tools で、外の場所を引数に取るスクリプトが確認なしに動くか（確認が出たら、セッションが待ちになる。作者は記録するまで押さない） |
| 2 | 会社A・auto | 外を Read・Write、原本に Write（新しいファイル）と Edit（あるファイル）、計画書.docx を Edit、`cat` で外を読む、`yomu` の skill でプラグインの補助ファイルを読む、`python3 -c` で原本を書き換える | 外を読み書きできないか。deny が日本語のフォルダ名でも効くか。プラグインの補助ファイルを読めるか。原本を書き換えたとき、Stop hook が戻すか |
| 3 | 会社B・auto | `junbi` の skill で設定を作ってから、外を Read する | 作ったその場で効くか。プラグインのスクリプトが `.claude/settings.json` を書くことを、auto モードの分類器が止めないか |
| 4 | 会社B・auto（新しいセッション） | 外を Read する | 開き直したときに効くか（3 で効かなかったときの裏付け） |

結果は `experiments/E6/結果.md` に書きます。
