# 実験 E1 の手順

DESIGN 13.2 の E1 を確かめます。ブラウザの道具の呼び出しを hook が受け取り、画面入力の守り（DESIGN 5章）を作れるかを見ます。

## 用意

- 試しの申請画面：`experiments/E1/page/`（架空の2画面）。`/usr/bin/python3 experiments/E1/serve.py 8765` で、127.0.0.1:8765 に出す（`cgi` を使うので Python 3.12 まで）。送られた値・添付・押したボタンは `~/.hojokin-e1/server.jsonl` に残る。
- 試しの会社のフォルダ：`~/hojokin-e1/会社/`（目印あり）。試しのプラグイン e1-probe を CLI で local の範囲で入れる。
- hook の記録：`~/.hojokin-e1/hooks.jsonl`（ブラウザの道具の入力と結果）、`~/.hojokin-e1/許可/`（画面入力の許可の控え）。

## E1a（デスクトップアプリのセッションで流す）

1. 内蔵ブラウザで画面1を開き、read_page で部品の名前を読む。
2. form_input で欄に入れ、もう一度読んで、入れた値が読めるかを見る。
3. 「拒否テスト」を含む入力を hook が拒むかを見る。
4. 「次へ」で画面2に移り、部品の番号が別の部品を指さないかを比べる。
5. 許可を求める確認が何回出たかを数える。
6. ターミナルの Claude in Chrome でも、hook が道具を受け取るかを見る。

## E1b

1. 添付：内蔵ブラウザで開いたファイルを選ぶ画面を、画面を操作する機能で操作できるか。Claude in Chrome の file_upload が動くか。
2. まとめて動かす道具（browser_batch）の中を、hook で1つずつ見られるか。
3. 作っている途中のプラグインを、hook が効く形でデスクトップアプリに入れて動かせるか（E4・E6 で、CLI で local の範囲で入れれば動くと分かっている）。
4. `/e1-probe:nyuryoku` を呼んだことを UserPromptSubmit hook で見分け、画面入力の許可を記録できるか。

結果は `experiments/E1/結果.md` に書きます。
