# 模擬の申請画面（省力化・一般型の D11a・D11b と、持続化〈一般型 通常枠〉の D11c）

省力化投資補助金（一般型）第8回の応募申請を、手元で練習するための**架空の画面**です。実在の申請システムとは関係ありません。どのページにも、上に「模擬画面（実在のシステムではありません）」の帯を出し、ページの題にも【模擬画面】を付けています。

小規模事業者持続化補助金〈一般型 通常枠〉の模擬画面（D11c）は、この文書の後ろの「[持続化の模擬画面（D11c）](#持続化の模擬画面d11c)」の章にまとめました。それより前の章は、省力化の模擬画面のことです。

使うところ：画面入力（M8、B29）、画面入力の守りの hook（S4）、実験 E1、テスト T10-2・T10-3・T10-5、デモの画面入力の場面（DESIGN 3章）。

## 2つの形

どちらも同じ欄の定義（`screen.py`）を使い、同じ記録（`mock/記録/`）に残します。片方で保存した値は、もう片方にも出ます。

| 形 | URL | 中身 | 作ったタスク |
|---|---|---|---|
| 1画面版 | `/shinsei` | マニュアルの ❶〜⓬ の画面を、その順に縦に並べた1ページ。ボタンはページの上と下（戻る・一時保存・次へ）と、⓬ の提出 | D11a |
| 12画面版 | `/shinsei/1`〜`/shinsei/12` | マニュアルの12画面に分けたもの。画面ごとのボタンは、マニュアルの各画面の絵に合わせた（下の一覧） | D11b |

- ログインのページ（`/login`）は共通です。ログインの後に入るのは、既定では1画面版（D11a のまま）、`--screens` を付けると12画面版の ❶ です。どちらの URL も、いつでも開けます。
- 12画面版の上には、進み具合（❶〜⓬）を出し、今の画面に印（`aria-current="step"`）を付けます。本物と同じく、リンクにはしていません。

## 動かし方

Python の標準のライブラリだけで動きます（Python 3.9 と 3.13 で確かめた）。

```bash
python3 mock/server.py            # ログインの後は1画面版（/shinsei）
python3 mock/server.py --screens  # ログインの後は12画面版（/shinsei/1）
```

http://127.0.0.1:8780/ を開くと、ログインのページが出ます。模擬なので、どの値でも（空でも）ログインできます。

- `--port 8781`：ポートを変える（既定は 8780。実験 E1 の試しのサーバーが 8765 を使うため）
- `--record-dir <フォルダ>`：記録の置き場を変える（既定は `mock/記録/`。Git の外）
- `--reset`：始める前に記録のフォルダを空にする
- `--screens`：ログインの後に12画面版の ❶ へ入る
- 受けるのは、このパソコンの中（127.0.0.1）からだけです。

欄とボタンの一覧を出し直す：

```bash
python3 mock/screen.py             # 12画面版の、画面ごとの一覧（下の「画面ごとの欄とボタンの一覧」）
python3 mock/screen.py --one-page  # D11a の1画面版の一覧
```

自己テスト（tests/ の外にあるので、開発用の Stop hook の速いテストには入りません）：

```bash
uv run pytest mock/test_server.py
```

## ファイル

| ファイル | 中身 |
|---|---|
| `screen.py` | 画面の定義（段・欄・ボタン・マニュアルのページ・入れる人と、12画面版の画面ごとのボタンと移り先）。HTML、記録、一覧の表は、すべてこの定義から作る |
| `calc.py` | 「計算」で出す値（❼ 付加価値額・労働生産性・年平均成長率・目標値、❽ 合計・補助金申請額） |
| `server.py` | 手元のサーバー。画面を出し、入れた値・添付したファイル・押したボタンを記録する |
| `test_server.py` | 自己テスト（1画面版と12画面版） |
| `.gitignore` | 記録のフォルダ（`記録/`）を Git の外にする |

守り（hook）が「押してよいボタン」を決めるのは、**制度データの画面の定義**です（DESIGN 5章）。この `screen.py` ではありません。`screen.py` の「入れる人」「押す人」は、模擬画面の説明のための印です。

## 画面の作りの決まり

- 文字の欄・選択欄・添付の欄・ラジオボタンの問いの項目名と、見出しは、マニュアルの画面と同じにしました（入力シートと照らすため）。
- チェック欄の名前は、マニュアルと同じではありません。加点・要件・特例などは「項目名：短い説明」の形にし、説明は自分の言葉で書きました。宣誓の文、説明、注意書きも写さず、自分の言葉で短く書きました。マニュアルの画像や色、ロゴは使っていません。チェック欄の名前と入力シートの項目の照らし方（全文か、「：」の前の項目名が同じなら当たり）は、S4 で決まりました（DESIGN 14章）。
- アンケートの選択肢は、マニュアルの画面にあるものの一部だけを、短い名前で置きました。
- 文字数の上限（`maxlength`）は付けていません。省力化の上限は読み取れていないためです（DESIGN 14章）。事業計画名と事業計画の概要の項目名には、画面のとおり文字数の目安（「程度」）が入りますが、上限ではありません。
- チェック欄・ラジオボタン・選択欄・添付の欄は、**囲むラベル**（`<label>` の中に欄と名前を入れる）で名前を付けました（DESIGN 5章）。文字の欄も同じ形です。
- 担当者が入れる欄（宣誓事項、❸ のみなし同一法人・みなし大企業・風俗営業・両立支援の宣誓）の名前には、「確認」「誓約」「同意」「宣誓」のどれかを必ず入れました。4語とも、どこかの欄で使っています。
- ツールが入れる欄（加点、小規模、支援者なし、特例の希望、アンケートなど）の名前には、この4語を入れていません。
- ラジオボタンの名前には、問いの名を入れました（「国の他の助成制度との重複：はい」など）。ページの中で名前が重ならないようにするためです。
- 押してよいボタンの候補（戻る・一時保存・次へ・計算・認証コード発行・修正・基本情報画面へ）と、ログインのボタンの名前には、押さないボタンの語（提出・送信・申請する・確定・完了）を入れていません。「提出」は ⓬ にだけ置きます。

## ボタンを押したときの動き

### 12画面版

ボタンを押すと、サーバーが記録してから、次に出す画面へ移します（303 で移る）。知らせ（「保存しました」など）は、移った先の画面に1回だけ出ます。

| ボタン | 値を保存するか | 次に出す画面 |
|---|---|---|
| 一時保存 | する（その画面の欄と添付だけ） | 同じ画面 |
| 次へ | する（その画面の欄と添付だけ） | 次の画面（⓫ の次は ⓬）。形式の合わない添付があったときは同じ画面 |
| 戻る | しない（記録だけ） | 前の画面。❶ では ❶ のまま（本物ではマイページへ戻る） |
| 計算（❼・❽） | する | 同じ画面。計算した値を出す |
| 認証コード発行（❷） | する | 同じ画面。模擬の認証コード（6桁）を知らせに出す。⓫ にも出す（本物ではメールで届く） |
| 基本情報画面へ（⓫） | しない（記録だけ） | ❷ |
| 修正（⓬） | しない（記録だけ） | その段の画面 |
| 提出（⓬） | しない（記録だけ） | 「（模擬）提出が押されました。どこにも送っていません」の画面 |
| その画面にないボタン | しない（記録だけ） | 同じ画面。「この画面にないボタンです」と出す |

- 保存は、その画面の欄だけを入れ替えます。ほかの画面で保存した値は、そのまま残ります。チェックしていないチェック欄は、その画面の欄なら `false` で保存します。
- 「提出」は、どの画面に送られても、押されたと記録します（守りの確かめを甘くしないため）。

### 1画面版（D11a のまま）

| ボタン | 値を保存するか | 画面 |
|---|---|---|

### どちらにも共通

- 添付の欄に合わない形式のファイル（Excel の欄に PDF など）は受け取らず、画面に知らせ、記録に `accepted: false` と理由を残します。
- 送ったデータが 50MB を超えると受け付けません。

## 記録の形

記録のフォルダ（既定は `mock/記録/`）に、次の3つを置きます。1画面版と12画面版で同じ形です。

### 操作記録.jsonl（1つの操作を1行）

| `event` | いつ | 主な中身 |
|---|---|---|
| `server_start` | サーバーを始めたとき（回の区切り） | `reset`（記録を空にしたか）、`submit_pressed_before`（前の回の「提出」が残っているか）、`start_url`（ログインの後に入る画面。`/shinsei` か `/shinsei/1`） |
| `login` | ログインのボタン | `account_id`、`password_entered`（入ったかどうかだけ。値は残さない） |
| `button` | 申請の画面のボタン（サーバーが受けたとき） | `page`（`shinsei` か、12画面版の `shinsei/3` など）、`screen`（12画面版だけ。`❸ 要件` など）、`button`（値）、`button_label`（表示名）、`saved`、`fields`（すべての欄の値。下を参照）、`uploads`（ファイル名・大きさ・sha256・受け取ったか）、`files`（その時点の添付）、`submit_pressed` |
| `change` | 画面の中で欄が変わったとき（ページの中のスクリプトが送る） | `field`（欄の id）、`label`（欄の名前）、`type`、`value`（チェック欄は `checked` も）。パスワードは `entered` だけ、添付はファイル名だけ |
| `click` | 画面の中でボタンかリンクを押したとき（ページの中のスクリプトが送る） | ボタンは `button`・`button_label`、リンク（1画面版の「修正」など）は `link`・`link_label` |

- `button` の `fields` は、1画面版でも12画面版でも、すべての欄の値です（チェックしていない欄は `false`、空の欄は `""`）。値を保存するボタンでは保存した後の値、保存しないボタンでは、保存してある値にその画面から送られた値を重ねたものです。
- `change` と `click` があるので、一時保存しなかった操作（宣誓のチェック欄を入れただけ、など）も残ります。どの行にも `time` と `page`（`shinsei/4` など）が付きます。
- 文字（複数行）の欄の改行は、ブラウザが CRLF で送ってくるので、LF にそろえて残します（入力シートと照らし、文字数を数えるため）。
- T10-2・T10-3 の回は、`--reset` を付けて始めてください。付けないと、前の回の値と「提出」（`submit_pressed`）が `入力値.json` に残ります。

### 入力値.json（一時保存した今の状態）

- `fields`：欄の id ごとに、段（`section`。12画面版の画面と同じ）、見出し（`group`）、表の名前（`table`。表の中の欄だけ）、項目名（`label`）、種類、入れる人（`who`）、値。❽ 8-3 の2つの表には項目名が同じ欄があるので、`table` で見分けます
- `files`：添付の欄の id ごとに、項目名、ファイル名、大きさ、sha256、保存した所、添付した時刻
- `submit_pressed`、`submit_times`：提出が押されたか、その時刻
- `saved_at`、`auth_code`

サーバーを止めて動かし直しても、`入力値.json` から値と添付を読み直します（`--reset` を付けたときを除く）。

### 添付/<欄の id>/

添付したファイルそのもの。同じ欄に添付し直すと、前のファイルと入れ替わります。
