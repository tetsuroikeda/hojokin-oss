# 模擬の申請画面（D11a：省力化・一般型の1画面版）

省力化投資補助金（一般型）第8回の応募申請を、手元で練習するための**架空の画面**です。実在の申請システムとは関係ありません。どのページにも、上に「模擬画面（実在のシステムではありません）」の帯を出し、ページの題にも【模擬画面】を付けています。

使うところ：画面入力（M8）、画面入力の守りの hook（S4）、実験 E1、テスト T10-2・T10-3・T10-5、デモの画面入力の場面（DESIGN 3章）。

## 「1画面」の読み方

TASKS の D11a の行で必ず置くもの（提出ボタン、確認・誓約・同意〈宣誓を含む〉のチェック欄、加点のチェック欄、ラジオボタンと選択欄、添付の欄、パスワード欄）は、マニュアルでは何画面にもまたがっています。そこで、次の2ページにしました。

- **ログインのページ**（`/login`）：アカウントID とパスワード。
- **申請のページ**（`/shinsei`）：マニュアルの ❶〜⓬ の画面を、その順に縦に並べた1ページ。進み具合（❶〜⓬）は文字だけで、リンクにはしていません。

12画面に分けるのは D11b です。画面の定義（`screen.py`）は段ごとに分けてあるので、分けるときもそのまま使えます。

## 動かし方

Python の標準のライブラリだけで動きます（Python 3.9 と 3.13 で確かめた）。

```bash
python3 mock/server.py
```

http://127.0.0.1:8780/ を開くと、ログインのページが出ます。模擬なので、どの値でも（空でも）ログインできます。

- `--port 8781`：ポートを変える（既定は 8780。実験 E1 の試しのサーバーが 8765 を使うため）
- `--record-dir <フォルダ>`：記録の置き場を変える（既定は `mock/記録/`。Git の外）
- `--reset`：始める前に記録のフォルダを空にする
- 受けるのは、このパソコンの中（127.0.0.1）からだけです。

欄とボタンの一覧を出し直す：

```bash
python3 mock/screen.py
```

自己テスト（tests/ の外にあるので、開発用の Stop hook の速いテストには入りません）：

```bash
uv run pytest mock/test_server.py
```

## ファイル

| ファイル | 中身 |
|---|---|
| `screen.py` | 画面の定義（段・欄・ボタン・マニュアルのページ・入れる人）。HTML、記録、一覧の表は、すべてこの定義から作る |
| `calc.py` | 「計算」で出す値（❼ 付加価値額・労働生産性・年平均成長率・目標値、❽ 合計・補助金申請額） |
| `server.py` | 手元のサーバー。画面を出し、入れた値・添付したファイル・押したボタンを記録する |
| `test_server.py` | 自己テスト |
| `.gitignore` | 記録のフォルダ（`記録/`）を Git の外にする |

守り（hook）が「押してよいボタン」を決めるのは、**制度データの画面の定義**です（DESIGN 5章）。この `screen.py` ではありません。`screen.py` の「入れる人」「押す人」は、模擬画面の説明のための印です。

## 画面の作りの決まり

- 文字の欄・選択欄・添付の欄・ラジオボタンの問いの項目名と、見出しは、マニュアルの画面と同じにしました（入力シートと照らすため）。
- チェック欄の名前は、マニュアルと同じではありません。加点・要件・特例などは「項目名：短い説明」の形にし、説明は自分の言葉で書きました。宣誓の文、説明、注意書きも写さず、自分の言葉で短く書きました。マニュアルの画像や色、ロゴは使っていません。チェック欄の名前と入力シートの項目をどう照らすか（全文か、「：」の前の項目名か）は、S4 で決めることです。
- 文字数の上限（`maxlength`）は付けていません。省力化の上限は読み取れていないためです（DESIGN 14章）。事業計画名と事業計画の概要の項目名には、画面のとおり文字数の目安（「程度」）が入りますが、上限ではありません。
- チェック欄・ラジオボタン・選択欄・添付の欄は、**囲むラベル**（`<label>` の中に欄と名前を入れる）で名前を付けました（DESIGN 5章）。文字の欄も同じ形です。
- 担当者が入れる欄（宣誓事項、❸ のみなし同一法人・みなし大企業・風俗営業・両立支援の宣誓）の名前には、「確認」「誓約」「同意」「宣誓」のどれかを必ず入れました。4語とも、どこかの欄で使っています。
- ツールが入れる欄（加点、小規模、支援者なし、特例の希望など）の名前には、この4語を入れていません。
- ラジオボタンの名前には、問いの名を入れました（「国の他の助成制度との重複：はい」など）。ページの中で名前が重ならないようにするためです。
- 押してよいボタンの候補（戻る・一時保存・次へ・計算・認証コード発行）と、ログインのボタンの名前には、押さないボタンの語（提出・送信・申請する・確定・完了）を入れていません。

## ボタンを押したときの動き

| ボタン | 値を保存するか | 画面 |
|---|---|---|
| 一時保存 | する（添付も受け取る） | 保存した値と「添付済み：ファイル名」を入れて出し直す |
| 次へ | する | 同じ。D11a は1画面なので、次の画面はない |
| 戻る | しない（記録だけ） | 保存してある値で出し直す |
| 計算 | する | 計算した値を出す |
| 認証コード発行 | する | 模擬の認証コード（6桁）を画面に出す。本物ではメールで届く |
| 提出 | しない（記録だけ） | 「（模擬）提出が押されました。どこにも送っていません」の画面 |

- 添付の欄に合わない形式のファイル（Excel の欄に PDF など）は受け取らず、画面に知らせ、記録に `accepted: false` と理由を残します。
- 送ったデータが 50MB を超えると受け付けません。

## 記録の形

記録のフォルダ（既定は `mock/記録/`）に、次の3つを置きます。

### 操作記録.jsonl（1つの操作を1行）

| `event` | いつ | 主な中身 |
|---|---|---|
| `server_start` | サーバーを始めたとき（回の区切り） | `reset`（記録を空にしたか）、`submit_pressed_before`（前の回の「提出」が残っているか） |
| `login` | ログインのボタン | `account_id`、`password_entered`（入ったかどうかだけ。値は残さない） |
| `button` | 申請のページのボタン（サーバーが受けたとき） | `button`（値）、`button_label`（表示名）、`saved`、`fields`（すべての欄の値。チェックしていない欄は `false`、空の欄は `""`）、`uploads`（ファイル名・大きさ・sha256・受け取ったか）、`files`（その時点の添付）、`submit_pressed` |
| `change` | 画面の中で欄が変わったとき（ページの中のスクリプトが送る） | `field`（欄の id）、`label`（欄の名前）、`type`、`value`（チェック欄は `checked` も）。パスワードは `entered` だけ、添付はファイル名だけ |
| `click` | 画面の中でボタンかリンクを押したとき（ページの中のスクリプトが送る） | ボタンは `button`・`button_label`、リンク（「修正」など）は `link`・`link_label` |

`change` と `click` があるので、一時保存しなかった操作（宣誓のチェック欄を入れただけ、など）も残ります。どの行にも `time` と `page` が付きます。

文字（複数行）の欄の改行は、ブラウザが CRLF で送ってくるので、LF にそろえて残します（入力シートと照らし、文字数を数えるため）。

T10-2・T10-3 の回は、`--reset` を付けて始めてください。付けないと、前の回の値と「提出」（`submit_pressed`）が `入力値.json` に残ります。

### 入力値.json（一時保存した今の状態）

- `fields`：欄の id ごとに、段（`section`）、見出し（`group`）、表の名前（`table`。表の中の欄だけ）、項目名（`label`）、種類、入れる人（`who`）、値。❽ 8-3 の2つの表には項目名が同じ欄があるので、`table` で見分けます
- `files`：添付の欄の id ごとに、項目名、ファイル名、大きさ、sha256、保存した所、添付した時刻
- `submit_pressed`、`submit_times`：提出が押されたか、その時刻
- `saved_at`、`auth_code`

サーバーを止めて動かし直しても、`入力値.json` から値と添付を読み直します（`--reset` を付けたときを除く）。

### 添付/<欄の id>/

添付したファイルそのもの。同じ欄に添付し直すと、前のファイルと入れ替わります。

## 内蔵ブラウザで読んだときの見え方（2026-11-03 に確かめた）

デスクトップアプリの内蔵ブラウザの `read_page` では、次のように見えました。DESIGN 5章の守りが頼る「囲むラベルの名前」は、どの欄でも読めます。

- チェック欄：`label` の下に `checkbox "on"` と、名前の文字（`generic "省力化ナビ加点：…"`）が並ぶ。チェック欄そのものの名前は「on」。
- ラジオボタン：`radio "はい"`（値が名前になる）と、名前の文字（`generic "国の他の助成制度との重複：はい"`）が並ぶ。
- 選択欄：`label` の下に名前の文字（`generic "組織形態"`）と、`combobox "--選択してください--"`（選んだ選択肢が名前になる）が並ぶ。
- 添付の欄：名前の文字（`generic "履歴事項全部証明書"`）と、`button type="file"` が並ぶ。
- パスワード欄：`textbox type="password"`。
- 提出：`button "提出" type="submit"`。

内蔵ブラウザの入力の道具（`form_input`）で、チェック欄・文字の欄・選択欄に入れ、「一時保存」をクリックすると、`change` 3行・`click` 1行・`button` 1行が記録に残りました。

## マニュアルの画面と違う所（模擬で変えた所）

S4・M8・E1 で、本物との差として気にかける所です。

1. **1ページに縦に並べた**。本物は12画面で、❶ と ❿ には一時保存のボタンがない（戻る・次へだけ）。
2. **宣誓事項は5行で、自分の言葉**。本物は13行ある。模擬では、どの行の名前も「宣誓事項N：」で始め、4語のどれかを入れた。本物の行には、4語のどれも含まない文の行もある（p.7）。本物の画面で、宣誓の行に囲むラベルがあるか、名前に4語が入るかは、E1 で確かめる必要がある。
3. **ラジオボタンの名前に問いの名を入れた**。本物は「はい」「いいえ」だけで、問いの名は見出しにある（p.11、p.18）。
4. **加点のチェック欄の名前は「項目名：説明」**。本物は説明の文だけ。本物の ⑧省力化ナビ加点の文には「確認」の語が入っている（p.13）。このため、本物の画面では、守りがこの加点を拒む見込みがある。
5. ❸ 3-6 の見出しには、本物どおり「確認」の語が入る。ラジオボタンの名前には入れていない。
6. **添付の欄は、入力にかかわらずすべて出す**。本物は、それまでの入力に応じて出る欄が変わる（p.20）。本物にある「削除」のボタンは置いていない。本物は選んだらすぐ添付されるように見えるが、模擬は一時保存を押したときに添付する。
7. 本物にある「検索」のボタン（法人番号・郵便番号・業種コード）は置いていない。業種の分類と地域別最低賃金は表示しない。7-1 の ③最低賃金の目標値も表示しない。
8. **文字数の上限は付けていない**（DESIGN 14章）。本物の画面では、事業計画名と事業計画の概要に文字数の目安が書いてある（p.14）。
9. 補助金申請額（D）は模擬の計算で、上限額を見ない（（B）の合計 × 補助率。小規模か最低賃金の特例なら2/3、ほかは1/2）。本物は経費の配分でも変わる（p.19）。
10. 選択肢は一部だけ（業種の中分類、アンケート）。
11. 「戻る」は保存しない、「次へ」は保存する、とした（本物の動きは、マニュアルからは読み取れない）。
12. ⓫ の認証コードは、メールの代わりに画面に出す。ログインは値を確かめない。
13. 本物にあるマイページ（新規申請・編集）は置いていない。ログインの後は、すぐ申請のページに入る。
14. 「修正」と「❷ 基本情報へ戻る」は、ページの中のリンクにした（本物はボタン）。
15. 担当者が入れる欄は、どれも囲むラベルで名前が読める。本物の宣誓事項は、チェック欄が表の別の列にあり、囲むラベルがない見込み（p.7）。

## 後のタスクへの申し送り

- 記録だけでは、欄を入れたのが担当者かツールかは分からない（たとえば、担当者がふつうにパスワードを入れてログインした場合や、宣誓のチェック欄を入れた場合）。T10-3 で「確認・誓約・同意のチェック欄とパスワード欄に入力がない」をどう見るかは、作者が決める（たとえば、T10-2 の回では担当者もそれらの欄に触れない、と決める）。手がかりとして、ログインは別の行（`event: login`）にし、ボタンごとにすべての欄の状態を残している。
- 模擬画面は、本物より守りに有利にできている（上の 2・3・4・15）。今のままだと、T10-3 は「4語を含む名前の欄を拒む」だけで通り、DESIGN 5章の残りの条件（入力シートでツールの欄とされていない欄は拒む、名前が読み取れない欄には入れない）は確かめられない。4語を含まない宣誓の行や、囲むラベルのない宣誓の行を足すかは、作者が決める。
- ページの中のスクリプト（`change`・`click` の記録）は、ブラウザの道具がスクリプトを実行するものではない。守りが JavaScript の実行を拒んでも、記録には関わらない。
