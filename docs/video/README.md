# デモ動画（ハッカソン提出用）

hojokin の紹介動画を、コードで作る道具です。映像・字幕・BGM はこのフォルダのスクリプトから作り、声は音声合成（Gemini、予備に macOS の say）で作ります。プラグインには入りません。

- 長さ：3分以内（提出の条件は3分以内・日本語）。今の版の長さは、build.py が最後に出す「全体 ◯秒」
- 構成：社長の道のり（申請の5つの段階と、それぞれの壁）→ hojokin → 段階ごとの解決（実物の出力）→ 社長の指摘を受けて直す（前と後）→ 採択の後 → PM のように自分から知らせる（実際の Claude Code の端末）→ その仕組み（フック）→ 学習（2件目の実際の応答）→ 始め方 → 作り方と守り → 終わり

## 何が実物か

画面と文は、架空のデモの会社（株式会社みずなら精工。東京都葛飾区の金属部品の町工場、18人。testdata/デモの会社_町工場）で、実際にプラグインを動かして得たものです。社長は実在の人ではなく、回答表から答える社長役のモデルです（tests/multiturn/run.py）。PM の場面だけは、社長の発言を1つ打って送る形で、対話の Claude Code を動かしました。

| 場面 | 出しているもの | どこから |
|---|---|---|
| 1 探す | 補助金の候補.docx | 申請書を書き終えた段階の会社のフォルダ（探す段階で作ったものと同じ） |
| 2 調べる | 概要と流れ.docx の「満たす要件・当てはまらない要件」の表（判定と理由に要領のページ） | 書類の段階の会社のフォルダの写しで、junbi の続きとして作ったもの（下の注） |
| 3 書類 | 入れた書類17件、整理した後の原本の置き場、不備の一覧 | 対話/shorui.md（17件を入れて確かめを頼んだ、実際の応答3つ） |
| 4 書く | 財務モデル.xlsx、計画書、根拠対照表.xlsx、審査役の確かめる観点と、実際の確かめの数 | 会社のフォルダ、agents/shinsa.md、記録/審査役の結果・記録/完成の記録.json |
| 指摘を受けて直す | 計画書・財務モデルの、直す前と直した後（スケジュール・直近実績・財務モデル・事業計画名） | 指摘の前の段階と、直した後の段階の会社のフォルダ（下の注） |
| 5 採択後 | 採択のお知らせ（架空の通知の上の部分）、実際の応答3つ | 対話/saitaku.md（架空の採択の通知を入れたときと、架空の差し戻しの文を貼ったときの応答） |
| PM | 「今日は何から？」と聞いたときの Claude Code の端末 | 対話/pm_terminal.json（rec_terminal.py が疑似端末で本物の claude を動かし、出たバイト列と時刻を記録。xterm.js で描き直す。待ち時間は詰める） |
| 仕組み | フックが Claude に渡す指示の文 | 対話/session_start.md（PM の撮影で開いたときの hook の実際の出力） |
| 学習 | 覚えた事実・書き方の決まり・1件目の質問、2件目（持続化）の実際の応答 | 記録/会社の記録.json、記録/質問の記録.json、対話/jizokuka.md |
| 作り方 | コミット・タスク・eval のケース・テストの関数の数 | git log、docs/TASKS.md、evals/、tests/（数え方は 素材.json の built._数） |

- 対話の引用は、`素材.json` に写した文が `対話/` の記録にそのままあるかを、build.py が確かめます（`**` と空白は除いて照らす）。`対話/` の写しは、応答から使う段落を、文を変えずに写したものです（省いた所は「（中略）」）。
- **PM の撮影**：今日の日付を 2026-11-25 に差し替えています（会社のフォルダの .hojokin/設定.json の「今日の日付」。実際の日付だと近い締切が無いため）。作者の全体の設定は読まない撮影なので、作者の全体の設定にある1行（「返事は必ず日本語で書く。」）だけを `--append-system-prompt` で渡しました。中身を調べられないコマンド（`python3 -c` など）は、確認の画面で止まらないよう、撮影の設定で先に断っています。作者のアカウントの表示（契約の名前・使用量・agents の数）は、同じ幅の空白に置き換えてから記録に書きます。答えのうち「損益計算書・貸借対照表が見当たらない」は、原本に決算書があるのに hook の必須の書類の照らし合わせが拾えていないもの（製品の直す所）なので、画面の右の札には出していません。
- **概要と流れ.docx**：申請書を書き終えた段階の写しで junbi の続きを流すと、Word の道具が「制度データの形が合わない」（kaku が様式の項目に足した「欄」）と「補助の対象にする経費が金額として読めない」で止まりました（製品の直す所）。そのため、書く前の段階（書類を整理した後）の写しで、同じ頼み（「概要と流れの Word と、書類の一覧・日程を作ってください」）を流して作ったものを使っています。
- **指摘を受けて直す**：社長役の頼み（スケジュールが細かすぎる、2023年度の実績、損益の内訳、事業計画名）を受けて直した前と後です。見た目の直しの多くは、指摘の後に作者が製品の道具を直し、その道具で同じ会社のフォルダを直したものです。前と後の計画書は、書体の置き換わりをそろえるため、製品と同じ見た目の写し（lib/yoshiki_word.py の layout_copy）を1回の LibreOffice の実行でまとめて PDF にしました。財務モデルも同じです。
- **学習の数**：覚えた事実と書き方の決まりの数は、説明の練習で決まりを1つ覚えた後の会社の記録から取っています（申請書を書き終えた段階では決まり0件）。
- 冒頭の社長の道のりと、STEP 4 の確かめの印（！→✓）の動きは、説明のための演出です（その下の「1回目の確かめで要修正◯件 → ◯回目で0件」は実際の記録の数）。

## 作り方

材料はリポの外の2つのフォルダに置きます（会話の記録・作者のパスが入るため、リポには入れません）。

1. 会社のフォルダ：申請書を書き終えた段階の みずなら精工 のフォルダ（作者の手元では `~/hojokin-デモ/段階/4_書く_完成4`）。
2. 材料のフォルダ（作者の手元では `~/hojokin-デモ/_記録/動画の材料_1108/組み立て`）：
   - `概要と流れ.docx`：書類を整理した後の段階の写しで、`tests/multiturn/run.py --turns 4 --budget 15 --model opus` に「省力化の準備の続きをしてください。概要と流れの Word と、書類の一覧・日程を作ってください。」を渡して作ったもの
   - `fix_*.png`：指摘の前の段階と直した後の段階の その1・2.docx を layout_copy にしてから、財務モデル.xlsx と一緒に1回の `soffice --headless --convert-to pdf` で PDF にし、`pdftoppm -r 110` で画像にして、スケジュール・直近実績・財務モデル・1ページ目を切り出したもの
   - `saitaku_tsuuchi.png`：testdata/デモの会社_町工場/採択後 の架空の採択の通知の上の部分（法人番号と事業計画名の行より上）
   - `会社の記録_練習.json`：説明の練習の後の会社の記録
3. 道具を入れる（初回だけ。docs/video で）：`npm install`（puppeteer-core と @xterm/xterm。この Mac の Google Chrome を使う）
4. PM の場面の端末を記録する。会社のフォルダは、作者の名前が入らない場所に写し、今日の日付を差し替える：
   ```bash
   cp -R <会社のフォルダ> /tmp/みずなら精工
   ```
   ```bash
   printf '%s\n' '{"今日の日付": "2026-11-25"}' > /tmp/みずなら精工/.hojokin/設定.json
   ```
   ```bash
   python3 docs/video/rec_terminal.py /tmp/みずなら精工 <このリポ> <リポの外>/pm_terminal.json "おはようございます。今日は何から手をつければいいですか？"
   ```
   記録は2つできます（置き換える前の `_そのまま.json` と、アカウントの表示を空白にした方）。リポの `docs/video/対話/pm_terminal.json` には、置き換えた方だけを写します。確認の画面で止まったときは、待たずに終わって終了コード 3 を返します。
5. 組み立てる（リポの根で）：
   ```bash
   HOJOKIN_TTS_PROJECT=<Google Cloud のプロジェクト> uv run --with numpy python docs/video/build.py <会社のフォルダ> <材料のフォルダ> --provider vertex
   ```
   出来たものは `docs/video/out/hojokin_demo.mp4`。

旗：`--provider gemini|vertex|say`（声を作る先）、`--keep-voice`（out/voice/ の声をそのまま使う。人の声に差し替えるとき）、`--no-video`（映像を撮らない）、`--keep-video`（撮った映像を使い回し、音だけ重ね直す）。

声の鍵：`gemini` は環境変数 `GEMINI_API_KEY`（無ければ `HOJOKIN_TTS_ENV` の .env）。`vertex` は `gcloud auth login` 済みで、`HOJOKIN_TTS_PROJECT` に Google Cloud のプロジェクトを渡す。鍵はリポに置きません。

今の版の声は、Vertex AI の Gemini 3.8 Flash TTS（声 Charon）で作りました。耳で聴けないぶん、Gemini 2.5 Pro に書き起こさせて台本と照らし、読み違えた場面は台詞を言いやすく直して作り直しています。

ほかに要るもの：ffmpeg、LibreOffice（soffice）、pdftoppm（poppler）。

## ファイル

| ファイル | 中身 |
|---|---|
| 台詞.json | 場面ごとの台詞（text は字幕、speech は読み上げ用）と、台詞の後の間 |
| 素材.json | 動画に出す実物の文（対話の引用、整理した後の置き場、書き方の決まり、作り方の数） |
| 対話/ | 実際の対話・端末・hook の出力の記録 |
| video.html | 1コマを描くページ。`seek(t)` に秒を渡すと、その時刻の絵になる |
| build.py | 声 → 時刻表 → BGM → 映像 → 音を重ねる |
| tts.py | 台詞を声にする（本文だけを送る。1秒あたりの字数が外れたら作り直す） |
| rec_terminal.py | 本物の Claude Code を疑似端末で動かして記録する（作者の全体の設定は読まない） |
| make_bgm.py | BGM を numpy で作る（冒頭はマリンバの疎らな旋律、本編は D–A–Bm–G の明るい進行） |
| render.mjs | video.html を 30fps で撮って mp4 にする |
| stills.mjs | 確かめ用に、指定した秒の静止画を撮る |
